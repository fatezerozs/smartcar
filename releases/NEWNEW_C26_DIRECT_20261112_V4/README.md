## 可复现的软件回退及单变量实验

从冻结V3 main.c提取实际误差→舵机请求代码，配合原servo_smooth_step建立左右镜像输入用例；输入25像素稳定误差，以及满舵后反向。命令cmd /c .diagnostics/s-turn/repro/run.cmd在V3运行，before.log记录6项失败。随后将用例接入V4同一生产helper，命令cmd /c .build/s-turn.cmd。

V3在25px只请求61.1us偏转，100ms到57.7us；满舵反向100ms只到另一侧约81.5us，即68%端点偏转。软件合同为25px至少80us请求、100ms有75us输出，反向100ms达到90%端点。这些是本轮工程响应目标，不是来自地图的物理出界阈值。

先仅改中大误差增益：25px请求107.8us，幅度通过，反向仍2项失败。再仅改大幅换向滤波/变化率：完整用例0失败；25px100ms到107.3us，反向100ms到另一端119.6us。

旧回放只复现和锁定软件控制链的舵量与响应缺陷，并未动态重建真实S赛道/车姿，不能将软件0失败等同于原实车问题完全消失。

## 实现

- 绝对误差<=10px保留0.22度/px；10—35px连续增至原捐赠0.50度/px；中大误差恢复转向能力，小误差不整体放大。
- 请求偏离中位>60us或距当前命令>80us时alpha0.60、最大35us/10ms；其余保持V3 alpha0.25及20us/10ms，2us保持区不变。整形仍PIT10ms、PWM50Hz。
- 不扩大机械端点：1430/1550/1670us不变；OFF立即回中并清滤波，仍撤两电机。
- 主循环与测试共用steer_target_us，避免测试副本与固件脱节。没有添加转弯定时脚本或盲转。
- UART8每5帧增加ms及req_us，保留servo_us，便于区分路线需求与实际软件输出。req/servo不是电位器实测前轮角。使用正式诊断字段，无临时DEBUG日志。
