# 规划器近场权威与转向波动处理：设计共识

2026-11-11，北京时间。状态：用户已逐项确认架构与行为方向；尚未实现、构建或验证。核查基线为 `.build/metric-experiment-20261111-r4/workspace/demo/mdk/competition/MPC_Metric_Experiment_Download.uvprojx`。决策入口：[ADR-0001](../../adr/0001-planner-near-authority.md)。

## 目标架构

保留现有转向算法及原双轮 PI。米制 CONTROL 的道路近场有效性以规划器近场预瞄为准；旧控制器近场不再独立否决米制动力。现有转向计算提供可用性、来源帧号与采集时间明确的有界转向候选，速度规划提供轮速候选；统一输出层继续执行授权、故障、候选身份与时效复核。算法模块没有直接写 PWM 的权限。

转向与速度必须能够关联到明确的视觉证据，但允许分别使用所需的有效视野。保留原转向算法不等于保留其内部所有旧道路准入、动力生成和故障升级权限；实施时需要拆清职责，同时验证转向算法的正常行为未被改变。

## 已确认的行为

| 场景 | 目标行为 |
| --- | --- |
| 首次启动 | 新鲜规划器近场与完整预瞄、有效转向、编码器及原有硬件/配置/授权前置条件满足后才能准入。应先评估输入，再决定真实输出授权，避免要求先进入旧 RUNNING 才能判断规划器是否可用。 |
| 规划器近场有效，转向短暂无更新或单个新候选被拒绝 | 上一转向仍可信时延续它并保留 PI；限制加速，不因该事件直接清零动力或终止会话。是否维持当前速度由综合约束决定。 |
| 转向证据持续减少 | 综合当前路径、历史路径剩余覆盖、转向变化和运动反馈，由同一规划层收紧允许速度并平滑减速；单次失败和丢帧数仅作证据，不独立成为停车命令，各层不重复施加降速。 |
| 普通转向证据不足，需要停止 | 优先降低速度参考，经原双轮 PI 跟踪至零速，保留仍可信的方向引导。不能为保持平滑超出剩余可控边界；不把普通波动自动升级成严重故障。 |
| 上述减速期间可靠候选恢复 | 平滑接回并逐步恢复加速能力，不重置整次运行；只有可靠新证据才能补回能力，旧帧不能续期。 |
| 上述减速已停稳 | 保留本次运行授权，进入零速等待恢复；保持零速度目标。新鲜近场、完整预瞄、有效转向及其他准入条件重新满足后平滑起步。 |
| 显式 STOP、物理撤权或严重故障 | 独立处置并保持原有优先级；零速等待恢复不能清除这些锁止，也不能重建已撤销的物理授权。 |

“零速等待恢复”是新设计概念，不得在报告中写成当前 r4 已存在的状态。实现时应区别于终止运行的停止/故障锁存，等待输出也不能沿用减速前的非零目标或缓存。具体零速确认、PI 停稳处理及提交约束需要在实现中验证。

## 范围与限制

- 本轮转向波动处理针对规划器近场有效时的转向证据问题。不顺带修改真正 near-invalid 的原有零驱动规则。
- 既有远场时间/距离预算、帧新鲜度、编码器与授权约束没有在本轮被取消。若独立停止/锁止原因同时成立，不能以零速等待恢复绕过；软停止或恢复重入也不能刷新旧帧、重置未满足退出条件的远场预算。
- 不实施新增不一致帧记录、二值图或路径保存；用户已取消该采集方案。
- 有效转角模型、舵机标定映射及几何轮速补偿后续完善；本轮不据此更换现有转向算法。
- 已确认但尚未实施的双固件/断电参数恢复设计单独存在，本记录不把它算作 r4 现有功能，也不授权硬件操作。

## 实施前需要补齐的依据

现有接口提供帧号/采集时间、路径、累计编码器里程、左右轮速及转向误差等信息，但没有完整的姿态、横向误差界与历史路径运动补偿模型。不能直接将编码器路程解释为可沿旧转向继续行驶的可信距离。

可用路径如何随实际运动消耗、转向候选如何判为仍可信、速度上限怎样受证据误差约束，需要形成可计算的接口与模型，并结合本车转角响应、延迟和减速数据验证。具体生产期限、距离、误差及恢复参数尚未选定；本记录不提供猜测数值。

## 后续验证范围

这些是后续需要执行的检查，不是已通过的结果：

1. 停车时可评估规划输入；首次准入不依赖旧近场，而仍满足新鲜完整预瞄与物理授权。
2. 直道单次候选失败保留仍有效的转向和 PI；真实入弯、S 弯不能按相同固定丢帧宽限盲目延续旧方向。
3. 无效/有效候选交替时，旧帧和不可靠恢复不会重置已消耗的证据或预算；同一原因不在多层重复降速。
4. 速度参考下降经原 PI 生效，普通波动不会无条件清 PI；减速恢复平滑，硬 STOP/撤权交错时旧候选不能重新提交。
5. 普通证据不足停稳后保持零速等待；满足全部恢复条件才平滑起步，停止锁存和严重故障不会被恢复图像清除。
6. 保留原近场失效、远场预算、帧/编码器时效、构型兼容和唯一 writer 回归，并分别取得目标构建、板端时序与实车能力证据。
