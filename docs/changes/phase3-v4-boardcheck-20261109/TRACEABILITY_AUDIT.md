## 可以与不可以回答的问题

及时读取且没有覆盖时，可以分析某段运行的目标/实测轮速、舵机命令、PWM命令、故障原因和粗略视觉统计。前轮确实导出了115条/1133ms的影子记录，说明该有限诊断能力可用，不说明以后每次都已自动归档。

目前不能保证回答“某次行驶在这个控制时刻究竟看到了哪张原始图、阈值和左右边界是什么、使用哪个完整参数快照、每个PI周期如何变化”，也不能保证复位后或下一次行驶后仍可完整回放。板端命令值不等于电气/机械测量值，原RAM轨迹只存少量视觉摘要，未保存全行边界和阈值；运行遥测帧计数与捕获序列语义也不同，不能仅按数字相等强行同步。

## 达到每次行驶追溯的必要补项

1. 每次运行建立统一Session及boot/run身份，固定固件/图像算法/配置SHA、尺度、采样配置、起止及停止原因；图片、编码器、PI和事件都引用共同身份和捕获序列。
2. 记录同帧完整原图及边界/阈值摘要，关联采集、处理、规划和编码器时间。图像保存频率、关键事件前后窗口和丢帧情况必须显式记录，不把抽样当全帧录像。
3. 对原PI目标/反馈/输出和状态事件做有界二进制记录，保留周期和序列缺口。日志进固定队列，记录丢弃/覆盖/写入错误，存储耗时不得进入控制中断或长时间阻塞前台。
4. 每次运行独立落盘或可靠停机导出，包含计数/CRC/结束标记及完整性校验；新一轮不静默破坏未归档记录。SD与控制并行写入的性能及中断收尾需要单独上板验收。

这是能力缺口清单，尚未实施新的记录固件，也未宣称已有Recorder构型可直接解决运行负载、掉电和同步验收。
