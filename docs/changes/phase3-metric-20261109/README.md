## 已实现的连接

| 模块 | 具体行为 |
| --- | --- |
| `vision_metric_io`编码器适配 | 从已捕获的`vd_speed_info_t`读取samples/sample_ms和total3/total4；明确Encoder3=左、Encoder4=右，按确认符号和显式ticks/m转换。速度使用累计计数差及实际时间，不把归一化raw计数直接当速度。采样序号0允许回绕，不冒充“尚无采样”。 |
| 路程历史 | 固定32条环形记录，保存整数累计轮端路程。查询capture时刻只接受精确样本或连续两样本内插值；不外推、不跨跳样插值。未来capture等待下一采样；过旧、断档、冲突、饱和累计值明确拒绝。保留signed轮速及累计绝对轮端路程，不把倒转或抖动抵消为零行程。 |
| 视觉快照 | 复用`sp_vision_preview`和原`vision_result_t`，调用者提供近/远采样行、单应矩阵和米制适用域；保留帧号/capture身份。地图revision改变需显式建立新几何会话。严格双边是现有离线适配契约，尚未批准替换主控视觉有效性规则。 |
| 输入组合 | 同一标定bundle revision绑定odom、视觉和planner身份；构造`vps_input_t`并携带capture时刻路程。有效新帧的历史未补齐时返回WAIT，调用者可沿上一接受帧继续处理；明确近场无效则立即转交监督层，不为几何对齐延迟无效事件。失败输出清空，不可当作部分成功数据使用。 |
| `vision_metric_pi`独立入口 | 接受规划输出的ticks/10ms目标；实测差分按实际elapsed归一化到同单位。直接调用未改动的`ws_pi_step_ff_ms`，显式分轮增益、PWM cap及前馈。绕开旧permille→目标换算、转向混合与重复目标斜坡；不复制另一份PI算法。 |
| PI候选与状态 | prepare/commit复核会话、revision、反馈身份、规划候选及监督预算。重复反馈返回WAIT，不重复积分；STOP立即清双PI并废弃旧结果；组合入口遇近场失效/锁存结果同周期清零诊断状态，正常WAIT保留状态。每条有效新反馈最多采用一次。 |

IO、影子执行器和诊断PI都要求单一串行所有者；init是显式新会话，配置在会话中不可变。相同revision只是来源契约，不验证物理标定准确度。调用者必须保证此bundle中的视野映射、距离尺度、增益与planner配置对应；绝不能将诊断PI与旧目标源同时用于同一物理输出。

## 下一步与自查

现在已具备原生快照输入及原PI算法的离线连接。接下来要明确板端单一调度所有者、原PI实例的目标来源切换/撤销，以及影子结果的低开销记录；再上板测实际执行开销、抖动和完整时延。最终writer的版本复核、物理C26准入及严重故障策略仍需与此入口共同集成。

Phase2还需完善映射适用域、相机/后轴与首可见点关系、真实闭环响应、停车及侧向参数。32条历史不是覆盖能力认证；需要按实际延迟检查保留窗口，不能靠外推补齐缺口。轮端路程用每次采样差的绝对值，静止抖动可产生微小增长，反转/滑移不能由该量单独判断。有效性、前馈、增益和预算参数应以连续运行和误停/超调数据收敛，避免无数据叠加保守限制。
