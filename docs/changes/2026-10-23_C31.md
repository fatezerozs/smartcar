## 2. 相对 C28 的代码和工具成果

### C29：连续道路支持、入口目标和运行诊断

- 双边/单边当前支持连续混合速度尺度，所有循迹目标共享上升包络，保留差速比例。
  原 C28 在同一路径双边行数 24→23 时目标约 89→63；C29 对应回归约 89→86。
  数值是模拟目标，不能当作实车加速度或卡顿已经消除的证据。
- 入口引导在当前相连白色余量内逐像素推进，替代固定偏移整行成败；候选仍需中央半宽余量、
  当前连接和足够有效行。它增加可用入口请求，不等于真实入环。
- 已训练、接受且新鲜的贝叶斯 ENTRY 可强化同侧当前暗岛确认；默认模型未训练，仍只观测。
- 行驶时诊断合并为有界、整数单行 `[RUN]`，记录目标/反馈/PWM、路径支持、转向、圆环、
  处理耗时和帧间隔，减少多行浮点输出；离线导入同时识别新旧格式。

详见 [C29 历史技术记录](../archive/versions/C26_29_ENTRY_AND_CONTINUOUS_SUPPORT.md)。

### C30：使用实拍缩略图复现相切内岛漏检

使用 21:51 批次手推/换视角数据。原会话 67 帧、既有保留清单 57 帧，没有将其标成自动驾驶连续轨迹。
当前回归选定 10 张 94×60 灰度夹具及校验；复制为 188×120 进入生产算法，不能恢复原始细节。

旧侧裁剪内岛的外边界首尾连线受像素量化影响，导致部分视角超过误差门槛。
改用全部当前有效点拟合，保留最大偏差、斜率等约束并增加 RMS 检查。
57 个独立静态姿态中 5 个入口视角结果改变、52 个不变；不是增加了 5 次真实入环成功。

C30 当时的独立控制回放使用默认观测参数，C31 已对齐当前 switch 参数。
旧对照图适合核对识别差异，其中模拟转向不能当作当前实车舵角。
见 [C30 记录](../archive/versions/C26_30_CAPTURED_TANGENT_ENTRY.md)、
[数据摘要](../../evidence/C26_30_PREVIEW_REVIEW.json)、
[夹具清单](../../tests/vision/fixtures/tangent-preview/manifest.json)。

### C31：已确认内岛接近 ROI 下端时的入口连续性

旧流程在内岛下端离开 ROI 后清空当前内岛证据，ENTER 仍在但入口引导归零，控制重新趋向直道。
新流程仅允许已确认且接近下端的同侧内岛，以匹配的当前轮廓、连接、宽度及外边界继续验证；
不能由底部截断暗块直接创建新入口，也不延用历史像素或固定转向时间。

增加真实 `vision_drive`/轮速适配/舵机 PWM 桩的截断连续性断言、反例和诊断字段。
当前参数下静态实拍回归有明确转向，但不代表真实车身已经切入或绕完圆环。
C26 启停、轮速 PI、既有速度/转向增益和舵机端点沿用 C29/C30。
见 [C31 记录](../archive/versions/C26_31_ENTRY_CONTINUITY.md) 和
[连续性复核](../../evidence/C26_31_ENTRY_CONTINUITY_REVIEW.json)。

### 静态图像采集与解析

`tools/capture_vision.ps1` 增加连续采集、时长与断帧超时、逐帧会话清单、原始字节保存、预览及离线重放。
它仍用于停车摆位或手推；启动采集会发送停车/接管/图像请求，不是纯被动监听工具。

见 [操作及局限](../reference/VISION_DATA_CAPTURE.md)。

## 3. 文档管理变化

原 `docs/` 根目录有 61 份文档，README 混有不同版本的“当前”启动、参数和能力说明。
本次将现状、提交快照和历史实验分开维护：

| 位置 | 职责 |
| --- | --- |
| `docs/PROJECT_EVOLUTION.md` | 持续维护的成品目标、现有模型、模块、状态、近期任务、候选技术、路线取舍与提交简略索引 |
| `docs/changes/` | 每次 push 的详细快照；本次和 2026-10-22 的 C28 总结各自独立 |
| `docs/reference/` | 8 份当前仍可使用的操作/技术参考，明确适用版本与工具范围 |
| `docs/archive/versions/` | 冻结的各 C26 阶段细节，附历史提示，保留原数值和证据 |
| `docs/archive/history/` | 旧架构、交接、基线和实验设计，不再作为当前操作入口 |
| `docs/INDEX.md` | 文档导航、归档清单与维护规则 |

README 缩减为当前版本、工程、阅读入口和必要现状。
61 份原文均有去向；不因“看起来过时”删除独有证据，删除的是重复维护当前现状的做法。
精确重复的旧贝叶斯 C29 状态段落合并为一处，移动后修复相对链接和根路径引用。
历史中拟退出的路线与已经退出的路线分开记录；C26 启动在实现 R4 之前不能标成已弃用完成。

`.gitattributes` 为选定灰度夹具增加二进制规则，防止 Git 换行转换改动原始像素；
不改变控制源码、运行参数或采集算法。

## 6. 证据层和复现边界

本次直接核对仓库 Markdown 原文与源码，JSON/夹具清单属于 `structured_parsed`，
校验和构建/回归为 `computed`，实车现状由操作者明确确认。
没有仅凭 `md_extracted` 确认公式或图像几何；旧实拍姿态的结论通过原始夹具和生产算法复现。
手推/静态/镜像/固定车头投影不能证明动态入环、全程稳定或真实最快速度。
主要风险仍为不同现场条件、同步不完整、模型与车体动态的差异，以及缺少当前完整路线验收。
