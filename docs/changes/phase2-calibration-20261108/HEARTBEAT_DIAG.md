## 诊断路径与判读

```mermaid
flowchart LR
    A[主机TX日志] --> B[无线UART收到h字节]
    B --> C[顶层命令处理到h]
    C --> D[运动中刷新心跳租约]
    D --> E[500ms超时判定]
    E --> F[停止时冻结快照]
```

候选 `PHASE2_HEARTBEAT_DIAG_20261109_1` 在隔离的历史响应源码副本中增加观测，不改生产源码。三组事件分别记录count、last_ms、max_gap_ms，使用同一GPT计时源；显式运动准入时清零，取消动作时冻结，并保留停止时间、租约时间、结束码和radio累计接收字节。仅停机后通过`@heartbeat_diag`读取，不在运动中增加诊断打印。

| 观测 | 含义与限制 |
| --- | --- |
| rx_h | 无线RX队列接受的字面h/H字节；可能包括其他命令中的字符，不等于校验过的心跳包。USB不计入。 |
| parsed_h | 非字段行状态下交给顶层处理的h/H；是处理路径观测，不是硬件接收时间。 |
| accepted_h | 活跃运动中实际执行租约写入的h；停机后的心跳不算有效续租。 |
| stop/lease/age | 停止判定时刻及保存的最后租约；无快照时age显示0，不作为活跃租约年龄。 |
| radio_rx | 准入与停止时UART累计字节，用于结合RX错误和主机日志分析。 |

若主机连续发送但rx_h中断，优先检查传输及RX路径；若RX连续而parsed_h中断，检查解析/调度；若parsed_h连续而accepted_h中断，检查状态和命令处理；若accepted_h及age与reason3矛盾，检查计时、调用顺序和快照。以上均为定位方向，尚不是本次根因结论。首条事件前的空窗不能由max_gap独立发现，必须结合准入时间、last_ms和计数。

快照不会被后续STOP或查询覆盖；下一次运动准入或复位会清掉该组诊断，故异常后先存档，禁止先RST。该附加文本不在原22字段轨迹CRC中，导出器明确标记`coveredByTraceCrc=false`，以原始串口日志和文件SHA256保存来源。仪器化会改变时序，不能把候选结果直接当成旧镜像无线可靠性认证。
