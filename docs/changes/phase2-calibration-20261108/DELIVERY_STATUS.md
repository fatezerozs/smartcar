## 代码入口、复现与效率

源码生成器位于`tools/prepare_phase2_response.py`、`tools/prepare_phase2_heartbeat_diag.py`、`tools/prepare_phase2_turn.py`；它们复制应用源码到隔离构建目录，生成Keil项目，**不下载、不启动**。快照保存在各候选证据目录，避免使用后来变化的主工程源码冒充原烧录输入。若依赖本地SDK、工具链绝对路径，必须重新定位；归档uvprojx是来源证据，不保证其他电脑直接打开可构建。

采集执行：[run_speed_response.py](../../../tools/speed_planning/run_speed_response.py)，默认dry-run，显式指定版本/现场构型才单发动作；[export_speed_response.py](../../../tools/speed_planning/export_speed_response.py)只回读，CRC及冻结信息一致后留存；[analyze_speed_response.py](../../../tools/speed_planning/analyze_speed_response.py)离线匹配采样身份。其他视觉/停车导出分析入口见对应文档。

软回调当前采用整数限额、无动态内存/新增阻塞日志；试验努力、期限、软阈值、舵机范围可停机配置及回读。周期遥测可关闭，完整记录事后导出，减少运动中通信负载。一般速度越界先回调，不锁停；STOP、租约/反馈失效及共同120异常兜底仍撤输出。详见[具体语义及限制](TURN_SOFT_CONTROL.md)。

当前软版冻结检查：Keil0错误0警告；响应/心跳/转弯三个独立Host程序共19350断言，19项Python工具检查，451行原生模拟轨迹CRC通过。计时器、编码器、PWM为替身，不代表地面控制稳定性。交付整合后的新增检查及Git提交信息另见提交记录，不把历史日志冒充本轮重新执行。

## 已知问题与下一步

1. **先改转弯回调连续性。** 左轮较快时共用限额压低右轮，右轮实际出现前进—暂停—再前进；左右独立回调尚未实现。反向计数故障与物理倒转分开记录，不通过延长测试或删除所有故障检测掩盖问题。
2. **再完成地面短弧。** 需要后轴轨迹与车身方向、带动力片段和滑行分开；尚没有实际曲率/侧滑/侧向加速度边界。用户说场地足够，但新场地数值尚未登记。
3. **补生产边界证据。** 电池实际电压、装载/地面覆盖，距离尺度误差，保守停车上界，动态视觉预算与运行构型端到端延迟仍缺；未测项保留未标定。
4. **Phase3单独验收。** 本交付不声称MPC主控制、Recorder或其他分支构型已接入上述候选参数。当前工作区存在其他开发改动，本次提交范围限Phase2工具/证据及必要导航。
