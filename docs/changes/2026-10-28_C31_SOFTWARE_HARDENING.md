## 2. 主要架构变化

- **帧与采集元数据：** 相机完成回调发布序号、回调采样时间和有效标志；运行时传递 stamp。复制前后用短临界区检查指针、序号和完成标志，拒绝可检测的软件换帧/ABA；这不等于取得 DMA 缓冲独占权。
- **启动准入：** C31 auto-track 使用 autonomous、route_trial、route_switch 三标志派生策略；不同序号的新鲜有效近远观测须在采集时间和前台时间上连续覆盖 3000ms，再检查 review、轮速和故障。默认 `MIDTERM_VISUAL_REVIEWED=0` 继续锁止；隔离 C26/C27、旧重启/清错和 UART arm/clear。switch 目标保留 C26 电平许可。STOP/故障锁止不等于已证明跨 MCU reset 的真实断电语义。
- **统一执行器：** 正常驾驶、motion、probe 的非零输出集中提交，按来源检查授权、状态与时效；归零先撤销授权、清缓存、重置 PI，再写三路零。C31 autonomous 拒绝诊断输出。临界区覆盖最后 PWM 写和 guard 快照发布，但不证明硬件同时生效或停车距离。
- **轮速/PI：** 目标发布与前台控制服务分离，只消费一次新编码器样本；采样间隔 10..20ms、最大样本年龄 30ms、控制停顿 50ms、未消费样本上限 1，超限 fail-closed。积分按实际毫秒计算，接受到达饱和边界的部分增量，保留原 headroom 断言、增益、符号及实际 PWM 上限。前台服务尚非已验证的硬实时调度器。
- **恢复与工具：** switch 既有两帧/40ms 零需求宽限标记 recovering，期间保持零输出，当前道路恢复后可继续；C31 无效观测仍故障。协议白名单及回归覆盖 C31，拒绝 C32/额外后缀；没有打开端口。
- **构建宏：** `auto`/`auto_track` 映射 `auto-track`；构建脚本拒绝基底受控宏覆盖并核对定义与输出路径替换，产物限于 `.build`。新增 auto-track 工程，显式关闭 start_switch/review；保留有消费者的 legacy 宏和编译约束，不擅改产品版本。

10-28 最终审查覆盖当时全部 38 个有文本差异的 tracked 文件、无文本差异的 switch 工程及未跟踪 auto-track 工程，并定点检查 CSI/PIT、SDK 缓冲回收、PWM/LDOK、共享状态、启动及宏消费者。

此处 R1/R2/R3 是**软件审查风险编号**，与演进档案第 4 节的同名实车目标分别理解：

| 风险 | 未关闭原因与所需证据 |
| --- | --- |
| R1：DMA 缓冲所有权 | 回调立即回收另一缓冲，没有前台持有/释放协议；IRQ 延迟、双完成跳过或 DMA 已覆盖但未发布时，序号稳定不能排除混合帧。PRIMASK/DMB 不停止 DMA。需可靠独占/状态协议或可验证的 IRQ 与复制时限依据。 |
| R2：采集时间戳 | capture_ms 是完成回调执行时的 GPT 读数，不是曝光或硬件锁存完成时刻；延迟 ISR 可能使旧图获得较新时间。时钟、可见性/缓存、漏中断和回绕仍需板端证据。 |
| R3：IRQ/PWM 实际时序 | 源码顺序依赖 CMSIS/编译器屏蔽与屏障语义，未审最终反汇编、非屏蔽异常或最坏执行时间；浮点/PI/PWM 临界区可能延迟 PIT/CSI。LDOK 写顺序不等于多通道同步、即时归零或已知停车距离。 |

主机 COPY_RACE/ABA 只覆盖软件发布。volatile 不自动提供复合原子性，不能用软件回归或纯构建关闭上述风险。
