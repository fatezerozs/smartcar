# Phase 3：监督状态机与影子规划联动

2026-11-09（北京时间）。本轮将[MCU影子规划接口](../phase3-interface-20261109/README.md)与既有监督状态机组合为`vision_planner_shadow.{h,c}`，由单一串行控制所有者管理轨迹状态、帧缓存和候选版本。已纳入实际主工程编译，**尚未接入板端调度、PI或PWM**。工作仍未提交、未合入main；本轮未访问串口、复位、烧录或运行车辆。

## 性能与稳定性取舍

用户明确要求：**减少过度保护，优先性能和稳定运行**。后续参数选择应以实测跟踪表现、误停、连续运行及资源开销为依据，避免为了保守而叠加任意门限或重复判断。本轮未新增固定生产速度/故障门限，也未凭该偏好猜测修改现有生产参数。

已消除影子入口对近、远视野的重复完整速度规划：共享`sp_preview_valid`只检查结构、范围和有限性；真正被选中的视野才执行一次规划。相同134断言组合测试，完整`sp_plan`调用由**128次降到32次**；优化前后5场景3750行CSV逐字节一致。这是调用次数和输出一致性证据，不是板端耗时降低75%的声明。

重复编码器样本返回WAIT，保留轨迹而不重复积分；视觉帧之间使用仍有效、扣除实际路程后的缓存视野；远场短暂失效沿既有有限降级规则处理，不因单帧far无效新增停止逻辑。STOP、失效数据及授权身份检查继续采用已建立的接口约束。

## 实现内容

| 内容 | 行为 |
| --- | --- |
| 显式会话与准入 | init只建立新的影子会话；arm需调用者明确准入声明、新鲜有效观测、近/全视野与捕获对齐路程。普通新帧不能自动arm，也不能清除停止/故障锁存。影子准入不授予真实C26或电机权限。 |
| 共享算法 | 复用原`sp_supervise`、规划及jerk代码；将Host管线已有的`sp_preview_advance`移到共享内核，原Host管线继续调用同一函数。公开原策略/规划配置校验，不复制另一套监督器或PI。 |
| 轨迹状态 | 每个不同编码器样本至多推进一次；dt来自控制时刻。新轨迹采用后更新control_revision；每次tick使前次结果失效。被抑制时清影子轨迹，近场恢复后以实际速度重新建立参考。 |
| 视野与路程 | 只缓存监督器接受的新帧。near-only选近场，全视野选完整路径；从缓存距离扣除capture到当前的路程，耗尽后拒绝旧视野。重复、旧帧不能续命。 |
| 结果复核 | 除接口版本/新鲜度外，重新检查监督器当前时刻的预算和锁存状态；准备时正常、发布时预算已到期的结果也会被拒绝。该检查不取代每周期tick。 |
| 故障结果 | 无效配置/身份、跳过编码器采样、不可行规划等清空诊断目标并锁存影子故障。近场失效走既有恢复/禁止动力语义；受控停止整形零目标，实际停稳仍由不同反馈样本确认。 |

接口要求单一串行所有者，内部不实现ISR/多任务并发锁。输入有效性、地面适用域和捕获路程仍由上游负责，来源标记不等于已标定。config在会话中不可变；需要新配置时显式结束/建立影子会话，不将init当作生产自动清故障入口。
