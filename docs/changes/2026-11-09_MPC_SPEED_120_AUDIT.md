# MPC 均速 120 tics/10ms 目标与架构审核

**术语说明：** `tics`是历史拼写，这里的ticks/counts均指编码器计数；`ticks/10ms`是每10毫秒的等效计数。全文“均速”指[全程编码器平均速度](../../GLOSSARY.md)，包含完整运行窗口内的起步、减速和停顿，不是瞬时速度或无打滑的地面速度。`cap`是速度上限，`jerk`是加速度的变化率；其他术语见[索引](../MPC_TERMINOLOGY.md)。

2026-11-09。结论：控制链具备继续提升速度的结构基础，但当前配置不能保证全程均速 120。当前交付修改的是 MPC 影子规划请求和验收目标；没有烧录或使能主动接管，现有板载速度不会因此改变。

## 已更新的目标

- `tools/speed_planning/phase3_profile.py` 生成的 `speedObjective.minimumMeanTicks10ms=120`，巡航请求名义值为 132，为弯道、起步及降级留出有限余量。
- 均速定义：从本次运行开始到结束的完整时间窗口，用方向修正后的左右轮累计计数均值除以窗口内的 10ms 数；包括起步、减速及窗口内停顿。不能只统计有效高速帧。编码器均速仍不等于无打滑的地面均速。
- 共同线速度请求采用 `(132-0.001)*100/max(11394,11389)`，约 1.15850 m/s；0.001 count 余量避免生成 float32 常量后超过轮速边界。原生整数目标向下取整，直线稳态约为两轮各 131，而非保证每轮精确 132。
- 120 的左右原始计数均值对应约 1.05342 m/s（候选滚动尺度）。近场降级 cap 仍为约 0.35114 m/s；不以均速要求覆盖停车、曲率和降级约束。
- 生成配置 `profiles/phase3-c26-shadow-20261109.json` 已同步，目标参与配置 revision 身份计算；历史证据快照保持历史含义。

## 当前瓶颈与潜力

1. **预瞄与停车约束是确定的瓶颈。** `tools/speed_planning/speed_planner.c:sp_plan` 要求在预瞄末端内停车。以当前单应矩阵、图像中心 x=94 和 full_rows 计算，首末采样前向位置约 0.746 / 1.175 m，直线有效路径跨度约 0.429 m。算法使用采样路径跨度，不能把最远点距后轴的 1.175 m 直接当成全部可用距离。按参考 brake=0.8 m/s²、latency=0.1 s、margin=0.05 m，cap 为约 0.70263 m/s，即约 80.04 counts/10ms。该计算是中心直线示例，不代表所有实际曲线路径。
2. **120 所需直线跨度至少约 0.849 m。** 使用 `D >= v*latency + v²/(2*brake) + margin`；名义 132 巡航约需 1.005 m。这里尚未加入 jerk、测量误差及抓地变化，因此只是必要条件。当前标定前向区域 0.697–1.297 m，总长也只有 0.600 m。需要扩展可靠近远场几何与标定，或在实测支持下修改动态模型；不能靠任意提高制动参数或取消末端约束通过验收。
3. **全程均速缺乏闭环保证。** 规划器仅追随即时请求并受空间 cap/加减速整形约束，没有整圈时间/路程预算或平均速度误差控制。即使使用名义 132，若其余时段为 92，低速时间占比最多约 30%；若为 40，则最多约 13.0%，尚未算起步停车和量化损失。需要完整赛道的速度分布与实测平均值，而不是单点峰值。
4. **曲率能力未确认。** 当前 lateral_accel=0.2 m/s² 为参考值，120 对应允许曲率约 0.180 m⁻¹（半径约 5.55 m，含 epsilon 前的近似）。紧弯会明显低于目标；几何补偿仍关闭，转向/抓地/制动/jerk 的动态标定未验收。
5. **执行架构可复用，但尚非已验收高速闭环。** 现有链路具有固定长度预瞄、制动反向传播、jerk 整形、10ms 编码器采样、分轮 PI、候选版本及过期校验、监督器降级/停机。计算有界（最多16点、整形24次二分），适合继续在 RT1064 上验证；这不是通用在线优化 MPC 求解器，也不是目标板 WCET 证据。采样最大间隔20ms、样本新鲜度30ms要求在实际相机/调度负载下验证。
6. **主动路径及动力能力仍待验证。** 默认 `VISION_PLANNER_RUNTIME/ACTIVE=0`；候选为 runtime=1、active=0。影子 pwm_cap=250、feedforward=0，并无在120附近地面闭环持续运行的验收。旧路线132上限和可到1000的PWM域只是软件范围，不能证明电机负载、PI稳定性或供电余量。旧路线快/弯/边缘132/104/92也不会自动满足全程120。

## 下一步验收重点

优先扩展并验证有效预瞄，使120及巡航请求在实测制动/延迟/jerk下可行；随后验证120附近轮速响应、转向曲率及运动时端到端时延，完成主动接管参数审核。最后对完整运行累计原始计数、总时长、cap原因、PWM饱和、降级占比和掉帧情况，验收均速至少120。当前报告不把这些未完成项目称为已保证。
