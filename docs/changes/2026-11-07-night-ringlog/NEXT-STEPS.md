# 下一轮调试执行方案

## 目标与保留功能

当前任务是稳定入环、沿环、出环并恢复普通循迹。C26 ON运行、OFF停止。必须保留可用的发车、直道、普通弯道与入环功能；本轮只整理方案，没有修改控制代码。暂不继续提速或调整相机。

## 版本结论

- RINGLOG1：用户反馈有进步，可作为入环比较基线，但出环未完成。
- RINGLOG2：用户反馈普通转弯和入环退步；不作为默认实车基线。
- RINGLOG3：已完成软件构建和回归，修复路宽模型、恢复前方优先搜索、调整仅EXIT分支方向控制；不能把软件通过等同实车通过。新材料的实际固件身份需先与串口开机标记对应。
- 五段视频初步观察及串口限制见[FOLLOWUP](FOLLOWUP.md)；前两段可见入环后停留，长片保留普通直弯能力，尚无完整环岛通过结论。

## 执行顺序与判据

1. **先整理现有证据，不要求重新跑车。** 解压串口快照，按固件身份、开机时期、C26行驶窗口分组；重复LAST_STOP只保留一次。列出停车时刻、reason/fault、目标和实测轮速。视频未对时的条目明确标记，不强行关联。
2. **定位停滞发生在哪个阶段。** 对详细RAM记录找停车前约2秒及恢复窗口，检查ring阶段、当前可见白路、真实/补线行、path_fallback、出口锚点及轮速目标。若现有串口不足，先使用已归档的CRC有效RAM导出；这些旧导出有明确版本，不能代替新版本实测。
3. **按证据选一个主要修改点。** 若卡在ENTER/FOLLOW，先修当前环内路径连续性和普通道路回退抢占；若已经形成合格出口但未进入EXIT，处理出口资格；若进入EXIT却转向不符，再检查近远端目标与最终舵机命令。不要同时改识别、控制器和速度参数。
4. **保持任务与瞬时路径分离。** 当前可见环路有效时保留任务；出口由当前连通白路与真实边界支持，不能用固定左右序列、定时舵量或旧像素盲走。目标是解释并修复停车根因，不能仅删除停车条件或强推PWM。
5. **修改后先做离线回归。** 覆盖普通直道/左右弯、原有入环、入口裁切、环内暂失边界、弯曲出口与镜像出口。检验当前路径与最终控制方向一致、路宽不从补线或环岛展开学习、C26 OFF仍停止。只运行与改动相关的必要验证；通过后归档新唯一版本，源码/AXF/MAP/校验值对应。
6. **最后做少量定点实车验证。** 先验证普通发车与入环未退步，再验沿环、出环、恢复普通路。连续记录成功和失败，出现回退保留上一可用版。确认完整通行后再逐步提速；状态显示FOLLOW/EXIT本身不算成功。

## 采集与注意事项

可用串口持续只读采集，自动重连，保留复位边界；不因采集擅自发车或复位。详细RAM导出需C26 OFF、主板保持供电、接好实际CMSIS-DAP，并使用对应固件版本的MAP。保持相机高度/俯角固定；停放画面的camera_w90不能替代行驶中的模型证据。SD状态正常不等于已独立回读SD文件。

后续GitHub交接以结论、改动范围、失败现象、证据索引和下一步方案为主；原视频保存在用户本地，不常规上传。已有原视频历史不强制重写。
