# 舵机单独标定（电机关闭）

本入口用于没有中位/限位记录的现场样机，不依赖编码器，也不使用摄像头误差来自动扫舵机。需要操作者观察机械转向；软件不能知道车轮是否正直、连杆是否顶死或舵机是否过流。

## 先决条件

1. 烧录含 `[PROBE] @probe pulse_us hold_ms` 帮助的新版本并 RST。当前未确认的舵机参数、电机 cruise/cap 仍为零，不自动运动。
2. 稳固架起整车，让车轮不接触地面，手、线缆远离转向连杆/轮子，准备切断供电。条件允许时单独断开驱动电机供电，保留控制和舵机所需供电；具体接线不由软件猜测。
3. 由操作者明确确认后才发送一次点动。1500us 仅是原 main.h 的 90 度名义脉冲，不是已经实测的机械中位，更不是保证不会顶死的安全值。若舵机规格不支持该接口，应停止，不发送。

## 协议与防护

`@probe pulse_us hold_ms`（普通字符，换行结束），只允许中期文字模式、DISARMED、没有锁存故障，且电机目标和上限都为零。

- 第一次请求仅允许名义 1500us。之后每次最多改变 50us，必须逐次由人观察，不自动扫描。
- 每次保持 100～1000ms；PIT1 和前台均检查时限，`h` 不能延长点动。串口失去通信也不会无限保持。
- 脉冲电气范围校验为 500～2500us，与原工程舵机接口一致；这不是机械允许全范围，绝不可把它当左右极限。
- 电机 PWM 在此路径始终为零；不能与驱动解锁同时生效。停止、图传、模式切换、改参、故障均撤掉点动；分段命令不能绕过同批停止优先。
- 点动不设置 hardware_confirmed，不修改相机参考轴或舵机驾驶参数。复位清除点动历史和全部 RAM 标定。
- PWM=0 只是停止发送控制脉冲，不代表机械立即回中、卸力或安全制动。出现响声、顶死、发热或异常动作，应立刻停测并切断相应供电。

电脑工具仅在显式 `-ServoReady` 且仅一条 probe 命令时发送，并验证新能力标记。它不能与 RunSeconds 混用，不自动发第二个脉冲。示例（仅操作者确认后）：

```powershell
.\tools\field_serial.ps1 -Port COM9 -Command '@probe 1500 700' -ServoReady -Seconds 1
```

工具等脉冲时限结束再查询 @status，不会把读取状态当成完成机械标定。保持逐飞助手断开；COM9 只是本次已确认端口，不固定在算法内。

## 机械确认顺序

先观察一次名义脉冲：车轮是否居中、有无顶死。若偏左/偏右，报告结果后再请求一个小步长。记录实际中位，然后小步验证两侧可用转角及“脉宽增大对应车轮朝哪边”。不要以机械硬止点作为工作端点，应保留余量。无必要不探索极限。

确认中位、保守两侧边界、符号后，才用 `@servo center_us min_us max_us sign` 提交驾驶配置。该提交本身不启动，但声明操作者已核实这些值。随后另行验证两电机前进方向、开环起步占空比，不能依据 PWM 推断车速。

架空和重新落地会改变相机观察；最终放回居中直道后必须重新采图确认两点轴。重新烧录的新版本还包含行内 Otsu 候选，因此不能直接复用先前固件的参考坐标。所有动态试跑都须另一次操作者就绪确认。
