# 用逐飞助手保存每次试跑日志

## 已确认的范围

用户截图为逐飞助手 V2.0.0.10 beta，串口助手接收区有“实时保存”复选框，可以优先用它作为串口日志记录入口。截图中的“显示时间戳”有助于之后对照视频。尚未操作该软件确认保存对话框、落盘格式、刷新周期或自动分文件行为，因此不能承诺勾选后一定自动按每次行驶拆分。

项目原有 `field_serial.ps1`、`run_prepared_training.ps1` 会把各自采集期间的串口数据写文件，但不是常驻的逐次试跑归档器。固件 RAM 中的循环 TRACE 也不是每次行驶的永久存储。

采用“逐飞助手实时保存 + 本地离线整理”的方式，无需改固件，也无需另一个程序争用同一 COM 口。

## 记录操作

1. 在车辆停止时，选择无线接收器对应的 COM 口。截图 COM11 是否为无线口需要以实际设备为准。参数使用 115200、8 数据位、1 停止位、无校验、无流控。
2. 保持“HEX显示”“HEX发送”“自动发送”关闭。接收区可勾选“显示时间戳”。日志记录使用文字模式，截图发送框的 `g` 是灰度图像命令；需要切回文字时，在停车状态将发送框改成 `t` 并发送。模式切换会影响运行，不能在行驶中作为记录步骤反复操作。
3. 在试跑前勾选“实时保存”，按软件实际提示选择文件，例如 `20261022-session01.txt`。先确认文件存在且接收数据后文件大小增加，再开始试跑。可连续保存多次，不必每次重开文件；这是连续串口会话，离线再分段。
4. 视频保留起步前和停车后的画面，记录与日志共同可见的时间参照。没有同步标记时只能粗略对齐。
5. 每次停车后继续接收 TRACE；看到相应 `[TRACE_END]` 才说明该批轨迹导出结束。不要刚停车就关软件或开始下一次试跑；否则 TRACE 可能来不及发完。输出的 TRACE 完整性还会按索引检查。
6. 全部试跑结束并接收完轨迹后，取消实时保存/按软件提示结束保存，再关闭连接。检查原始文件中有 `[RUN]`、`[SPEED]`、`[LAST_STOP]` 等文字。若无任何数据，先排查无线链路、固件日志模式和串口所有权；保存选项本身不会使固件发出数据。

同一串口由逐飞助手独占时，不同时运行 `field_serial.ps1` 等连接它的脚本。本次没有打开串口、发送车辆命令或操作用户截图中的软件。

## 一键整理

双击 `tools/导入逐飞日志.cmd`，选择已经停止保存的 txt/log 文件。程序优先使用本机 Codex 随附 Python，没有时使用 PATH 中的 Python 3.9+；无额外 Python 包依赖。

也可命令行执行：

```powershell
.\tools\import_seekfree_log.ps1 -InputLog 'D:\试跑\20261022-session01.txt'
```

或：

```text
python tools/import_seekfree_log.py "D:\试跑\20261022-session01.txt"
```

默认在仓库 `recordings/seekfree-日期-时间/` 新建归档，每次导入新建目录，不覆盖原文件或旧归档。`recordings` 中的记录默认忽略 Git，不要依赖提交代码备份录像与日志。重要记录另行备份。

输出包括：

- `source-original.bin`：源文件原始字节副本；`summary.json` 保存来源与 SHA256。
- `session.log`：整场会话的 UTF-8 文字版本，保留接收时间前缀。
- `segment-001/serial.log`、`run.csv`、`speed.csv`、`turn.csv`：每段软件运行观测及对应采样，缺少某种采样时不创建空 CSV。CSV 中保留原始字段、源行号及时间前缀。
- 每段 `summary.json`：观测起止时间、结束依据、偏差/转向范围、样本数量。
- `traces/`：复用现有分析器独立导出每批延迟 TRACE 的 CSV 和完整性结果，文件名带固件 run 编号。TRACE 与实时 segment 不强行按猜测关联。

导入器默认识别 UTF-8、带 BOM 的 UTF-16、GB18030。其它编码可通过 Python CLI 的 `--encoding` 指定；HEX 转储或图像二进制不是受支持的输入。

## 分段准确性

工具通过 `[RUN]` 或 `[DRIVE] state=1` 开始一段；通过新的 `[LAST_STOP]`、停止状态或 STOP 回执结束。重复的旧停车记录不会重复分段；启动日志与明显时钟复位分开处理。

两次 RUN 时间戳相隔超过默认 1500ms，会作为“遥测缺口”拆成候选段，不能据此证明中间真的停车；可用 `--gap-ms` 调整。一次真实试跑因此可能产生多个候选段，短暂停车但丢失全部停止证据时也可能无法分开。不要把文件夹数量当成精确试跑次数。

当前固件不输出完整的物理起止事件，工具始终标记 `physical_start_confirmed=false`、`physical_stop_confirmed=false`、`whole_run_guaranteed=false`。记录中途开始、无线丢包、提前关闭及循环缓存覆盖不能由上位机补回。若需要严格按每次真实行驶自动归档，还需落实 `RUN_START_END_ASSESSMENT_20261022.md` 的固件事件方案。

RUN 的 `pwm` 是控制需求；SPEED 的 `pwm_R/L` 才是实际输出千分比。编码器数据单位保留计数/10ms；转向为指令，偏移为图像估计，不能直接输出 m/s、实际转角或厘米偏移。

## 本次验证与来源层

自动化测试覆盖多次行驶、重复/陈旧停车记录、时间戳前缀、时钟回绕/复位、遥测中断、记录中途结束、原始字节保留、重复导入、延迟 TRACE 完整/截断及中文编码。未做实际串口或逐飞助手保存功能的端到端验证。

保存入口以用户提供的原始截图为布局证据；本地官方 README 用于确认串口助手/波形保存的功能区别。没有使用 PDF 或仅 `md_extracted` 的公式、表格和数值结论；分段和导出测试属于 `computed`。实时保存的具体落盘行为仍需第一次实际记录时验证。
