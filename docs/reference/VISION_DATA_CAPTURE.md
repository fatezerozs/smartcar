# 赛道图像采集

`tools/capture_vision.ps1` 接收现有逐飞 V2 的 94×60 图像。默认端口为操作者确认的 **COM10**，115200 / 8N1，无流控。脚本先停车、确认串口控制权，再请求图像；不发送启动或心跳，结束时恢复文字输出并关闭串口。

当前图传是阻塞调试功能，图像模式会撤销运行输出。此工具用于**静止摆位或手推采集**，不用于自动驾驶中的录像。运行前关闭逐飞助手等占用同一端口的软件。仅修改脚本不会连接小车；执行采集命令才会打开串口并发送停车、接管和图像请求。

## 使用

在项目 `smartcar` 目录运行，连续采集最多 120 秒：

```powershell
.\tools\capture_vision.ps1 -Port COM10 -Mode g -Frames 0 -DurationSeconds 120 -Preview
```

`-Frames 0` 表示不限制张数，仍受时长限制。默认仅采一张；也可以指定 `-Frames 20 -DurationSeconds 120`，张数或时长先到即结束。默认连续 12 秒收不到完整帧则报错，必要时通过 `-FrameTimeoutSeconds` 调整。按 Ctrl+C 可中止，已保存文件保留。

`-Mode g` 保存灰度缩略图，优先用于数据集；`b` 为二值图，`o` 为叠线图。模式在会话中固定，不交替发送模式命令。灰度也是固件输出的 94×60 缩略图，并非摄像头全分辨率原图。`-Preview` 额外生成 752×480 的最近邻放大预览，不增加训练数据分辨率。

可以把车停在直道、左右弯、十字、圆环入口等位置，改变横向偏移、车头方向和光照，分批采集。每次运行生成独立会话，避免覆盖。

## 输出

默认保存在 `.build/field/camera-模式-时间-随机后缀/`；`-OutputDirectory` 可指定会话父目录。

| 文件 | 内容 |
| --- | --- |
| `frame-000001.gray` | 5640 字节，逐行排列的 94×60 像素 |
| `frame-000001.png` | 同一帧的可查看图像 |
| `frame-000001.preview.png` | 可选放大预览 |
| `frames.csv` | 逐帧编号、会话、主机接收时间、文件名和待填写标注 |
| `received.bin` | 请求图像后实际读取的串口字节，包含噪声和未完成尾帧 |
| `session.json` | 端口、模式、时间、张数、字节统计、结束原因或错误 |

CSV 的 `state`、六个模型特征和 `notes` 初始为空。识别结果不是人工真值，脚本不自动生成正确标签。人工核对赛道类别、边界/中线等标注后，才可作为相应任务的训练数据。训练集和验证集应按采集批次分开。

这些图像清单**不能直接交给 `fit_track_model.py` 训练**：它还需要真实提取的特征和人工状态标签，且默认只统计间隔不超过 100ms 的状态转移。低帧率图传不提供这种连续时序；CSV 时间是主机收齐包的时间，不是相机曝光或板端时间，也没有同步的轮速和舵机记录。

## 断包与离线验证

接收端按固定包头和长度拆包，支持跨读取分包、连续多包，跳过包头前噪声。未完成帧不会保存成图像。协议没有校验和或帧号，因此无法保证检测像素丢字节/损坏，或计算真实丢帧数；噪声统计也不是丢帧统计。会话结束时尚未解析的字节数记为 `buffered_bytes`，其中可能含不完整包或因张数限制未处理的数据。

离线重新解码某次记录，不打开任何串口：

```powershell
.\tools\capture_vision.ps1 -ReplayPath '某次会话\received.bin' -Frames 0 -DurationSeconds 120
python -m unittest discover -s tests/vision -p test_capture_vision.py
```

离线解码重新生成主机时间，不能恢复原始接收间隔；原始时序应查看原会话 CSV。接入实车后的端口握手、断链超时和 Ctrl+C 收尾还需现场验证。
