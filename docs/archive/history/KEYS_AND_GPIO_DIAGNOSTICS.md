# 四键操作及 B11 现场诊断：IO_KEYS_V2

本页覆盖旧文档中“按住 C12/松开停止”和“只选档、串口触发点动”的操作。用户已经确认使用按一下启动、再按一下停止。

## 已确认的问题与尚待实测的原因

用户上电串口出现 `[MODE] C26/C27`，说明烧录程序包含模式选择逻辑。旧实现只读取 C26/C27 和 C12，没有给 C15/C14/C13 绑定按键动作。模式选择仅限制允许的控制路径，不会自动执行点动。另一个不匹配是旧实现把原理图上的瞬时 C12 按键当成了保持使能开关。

B11 对地仍约 0.55V，尚未确认根因。内部 47kΩ 上拉与图中 10kΩ 下拉的理想分压约为 `3.3×10/(47+10)=0.579V`（computed），与测量接近，但也可能是脉冲平均值或硬件漏电，不能据此认定故障。原理图显示 B11 在 4.7kΩ 基极电阻之前，不能把 B11 电压等同于 VBE。

## 当前按键与拨码

按原理图的 MCU 引脚定义，不根据实体按键上的 S 编号推断：

| 引脚 | 功能 |
| --- | --- |
| C12 | 按下并消抖后切换启停；上电默认停；松开保持状态 |
| C15 | 已使能时再次执行当前档位动作；观测档输出诊断 |
| C14 | 停止时增加暂存测试值：舵机 +50µs，电机 +10‰ |
| C13 | 停止时减小暂存测试值；调值本身不产生输出 |

两位拨码 C26/C27：OFF/OFF 观测，ON/OFF 舵机，OFF/ON 电机，ON/ON 整车。ON 接地，输入开启内部上拉。原始拨码变化会清除按键使能并撤输出，切回原档不会恢复旧运行。

舵机档第一次动作使用 1500µs，后续仍受原有单次步长校验；电机档初始为 30‰，默认测试实际 MOTOR1 通道，采用当前配置的方向电平。这不是已经确认的左/右轮，也不是自动确认前进方向。按键动作持续 300ms 后结束，C15 可显式请求下一次动作；电机仍受原有静默期限制。测试第二路可用 `@wheel` 明确指定通道。

点动档仍要求巡航和占空比上限均为零。若恢复了可行驶配置，按键会显示 REJECT，需先在停车状态调整为测试配置（例如通过既有 `@motor` 命令）。第一次舵机点动前就调离 1500µs 也会被原有首脉冲规则拒绝。所有拒绝都会打印 `[KEY]` 结果及 cap/cruise/faults/ready，不能把无输出视为按键没有被读取。

整车按键启动仍要求完整标定、配置、连续有效新鲜图像和无故障，使用显式本地启动、不依赖串口心跳；帧超时和总运行时限仍有效。清除锁存故障仍使用显式串口 `c`，按键不会偷偷清故障。图像模式/完整赛道观测/分段调参中不接受按键启动。

C12 停止在 30ms 消抖确认后由 PIT1 逻辑撤输出，松开不再停止；它不是独立硬件断电急停。开机已经按住 C12 不计为新按下，须松开后重新按下。

## 本轮 GPIO 修正

- 初始化 B11 为推挽低，C15/C14/C13/C12 为上拉输入。
- 显式将这些板级信号归属普通 GPIO1/2。上游 `fast_gpio_init()` 会通过 GPR26/GPR27 切到 GPIO6/7，而普通 `gpio_init()` 自身不负责切回；本轮仅清除板级拥有的目标位，不修改整组 GPIO 归属。是否原板遇到该问题，需看读回值，不能当作已证实根因。
- 独立 `board_controls` 处理按键动作，`board_diagnostics` 处理诊断输出，`board_io_hw` 处理寄存器适配，保持功能分层。

## 烧录后先看这三类输出

1. `[BOOT] io=IO_KEYS_V2 built=...`：确认使用新固件，而不仅仅是旧 `[MODE]` 帮助。
2. `[IO_KEYS_V1] C26=... C27=... mode=... keys_C15_C14_C13_C12=... press=... enable=...`：四键松开通常为 1111，按下一键对应位变为 0；消抖后该键 press 计数增加。拨码两路应各自随切换在 0/1 间变化。
3. `[B11] level=... mux=... dir=... out=... fast=... pad=...`：静音状态预期 mux=5、dir=1、out=0、fast=0、level=0。它们是数字寄存器/输入读回，不是模拟电压测量。

停车文字模式每 500ms 输出输入诊断；运行中避免增加这组多行输出，图像模式也不混入文字。C15 在观测档可再次请求诊断。

- 若拨码/按键原始电平完全不变，先核对实际测量引脚、板型、插接、公共地与输入归属。
- 若原始电平改变而 press 不增，检查按下/释放是否超过 30ms，再核对扫描中断是否运行。
- 若 press 已增但显示 REJECT，根据 cap/cruise/faults/ready 和视觉检查处理，不能归因于按键电路。
- 若 B11 的复用/方向/输出/归属不符合预期，定位后续哪个初始化重新配置了该脚。
- 若读回全部正确但外部仍测 0.55V，优先示波器区分直流与脉冲，复核实际测点、公共地、核心板连接和 GPIO/主板漏电。不要继续靠周期性重写 GPIO 掩盖问题，也不要直接短接正在输出的引脚。

本轮源码与主机检查不能证明噪音已消失。仍需要新固件的 `[IO_KEYS_V1]`、`[B11]` 输出，以及 B11 波形/电压，才能继续定位。
