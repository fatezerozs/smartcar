# 无线零接收现场检查（2026-10-22）

## 最新复测：无线回传已恢复

操作者要求再次测试后，COM10 在相同 115200/8N1、DTR/RTS 关闭条件下开始持续收到详细日志；COM11 同时收到 `owner=radio` 的简要遥测。无线查询返回 `MIDTERM_C26_21` 帮助信息。单独一次 2.5 秒的 COM10 状态采集收到 6876 个 ASCII 字符，链路回执为：

```text
[LINK] port=radio owner=radio rx=14 tx=674567 overflow=0 errors=1 tx_rejected=24
```

这证明当前无线收发与日志回传已经可用。`errors=1` 和 `tx_rejected=24` 是累计计数，说明本次上电期间有过硬件接收错误和发送入队拒绝；不能据一次快照判定它们现在仍在增长，也不能宣称全程无丢失。之前零接收阶段未收到的数据不能补回。

本轮未修改代码、烧录或保存模块配置，未实测 D26 电平，因此尚不能确定恢复前具体是哪一处硬件/连接状态发生变化。当前 C26 OFF、控制器 state=0、两路 PWM=0，owner=radio；PC 串口已关闭释放。复测证据为 `.build/wireless-retest-20261022-174703.log` 和 `.build/wireless-link-status-20261022-174733.log`。

以下保留恢复前的诊断过程，不能作为当前仍故障的结论。

操作者确认主板及车载无线模块供电，随后将 C26 置于 OFF，退出逐飞助手并按过核心板 RST。测试没有发送启动、心跳、点动、调参或持久保存命令，没有修改或烧录固件。

## 实际结果

- COM10 曾因访问被拒绝无法打开；退出串口软件后可正常打开。这一阶段端口访问障碍已消失。
- COM10 在 115200/8N1/无流控下被动接收，以及分次发送 `!`、`?` 后，均为零接收。
- 电脑侧 DTR/RTS 的其他组合也没有收到数据。这里是 USB 串口的主机侧控制线，不是车载 D26 电平；不能用这个试验推断 D26 高低。
- 复位监听阶段：COM10 收到 0 字节，COM11 收到 4828 字节，内容包含持续更新的 `[TELEM]`、相机帧数、`state=0 faults=0 owner=radio motion=0`。证明主板应用和有线遥测正在运行。
- COM11 的停止和接管命令得到应答；详细日志确认车上固件为 `MIDTERM_C26_21`，C26 原始电平为 1（OFF）、模式 OBSERVE，两路输出为零。
- 在有线接管为 `owner=usb` 后，从 COM10 发送无线接管命令；后续 COM11 明确报告 `owner=radio`。最终有线 `?` 应答为 `[LINK] port=usb owner=radio rx=10 ...`。这证明无线命令至少能够到达主板业务层；切换后旧 USB 队列内容仍可能继续输出，不能根据前几条详细日志断定接管失败。
- 整个过程中 COM10 仍无接收字节。问题集中在主板到电脑的无线回传路径，尚未定位具体失效元件或引脚。

## 当前判断

不是仅由上位机“实时保存”未勾选造成。主板日志生成、有线 TX/RX、无线 RX 到业务层至少已获得直接证据；无线回传尚无成功证据。

`app_link_board.c` 在 D26 为高时拒绝所有无线 TX，D26 低且 UART8 TX 就绪才写入。线路依据为 MCU D16/TX → 模块 RX、MCU D17/RX ← 模块 TX、D26 ← 模块 RTS。现有测试不能直接读取实物 D26，因此 RTS 持续高是待核实原因，不能宣称已经测到。也需检查 D16 到模块 RX 的接触和模块回传状态。

下一步保持 C26 OFF，核对模块接线、供电及 RTS 实际电平；不要为试通而强行短接 RTS 或在软件中绕过门控。若需要固件提供更直接证据，可另加经有线端查询两路 RX/TX 计数、TX 排队/拒绝、D26 电平的只读诊断，再构建并由操作者确认烧录；本轮尚未做此改动。

当前控制端最终为 radio，文字模式，两个 PC 串口均已关闭释放；未用代码更改参数，诊断 STOP 可能保留软件停止锁存。
