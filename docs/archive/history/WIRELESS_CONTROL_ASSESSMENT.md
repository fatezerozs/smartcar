# 按键回退与无线控制评估

## 当前回退结果

用户已实测 B11 为 0V、蜂鸣器正常。本次保留该修正：普通 GPIO 银行归属、B11 推挽低初始化及寄存器诊断。

四键扫描、消抖计数、C12 启停锁存、C15 执行、C14/C13 调值及 `board_controls.c/.h` 已清除；C12 不再接入 PIT1 控制，也不再是串口解锁的门槛。C12～C15 不再由本轮板级初始化占用。

C26/C27 拨码选档和切档停机仍保留。运行入口不再安排恢复配置后的自动启动；上电和恢复 Flash 配置后都保持停止。显式串口 `a` 仍要求有效配置、连续有效图像和无故障；相机/控制租约、指令心跳和最长运行时限保留。

固件启动标记为 `io=UART_CONTROL_BASE_V1`，输入诊断为 `[BOARD_IO]`，没有按键动作。不要再按旧 IO_KEYS_V2 文档操作。

## 无线串口是否可用

**软件具备基础，可用于启停、调参和观测；完全替代拨码选档尚未实现。**

| 能力 | 当前情况 |
| --- | --- |
| 无线 UART 接收与回传 | 已有 UART8 板级适配、独立 RX/TX 队列和中断 |
| 有线/无线控制权 | 停车时 `x` 申请当前端口；行驶时拒绝另一端抢占 |
| 停止 | 任一端口 `s`、`!` 或 Ctrl-C；同一批命令停止优先 |
| 整车解锁和续租 | 控制端 `a`、`h`；错误端口的心跳不能续租 |
| 参数与点动 | 现有 `@...` 命令；完整行验证，仍受标定/限幅/点动条件约束 |
| 文字/灰度/二值/叠线 | 现有 `t/g/b/o`；图像模式先停止运动 |
| 中期/完整算法观测 | `m/f`；完整模式不驱动，不是四档执行器模式选择 |
| 观测/舵机/电机/整车四档 | 目前仍由 C26/C27 决定；无线不能覆盖拨码 |

当前代码约定：115200、8N1；UART8 TX=D16、RX=D17，D26 为 RTS。代码的电平/供电约定及模块连接见 DUAL_UART.md；本轮没有连接实际 COM 或验证模块配对、空中链路和外设接线。软件回归通过不能证明物理链路已经可用。

## 可以先验证的无动作流程

1. 使用两位 OFF 的观测档，停止自动发送与 HEX 发送，用普通字符在无线端发送 `?`，检查 `[LINK] port=radio` 回复。
2. 单独发送 `x`，等待 `owner=radio`；不要在同一包后拼接启动或点动。
3. 再发送 `?` 或 `t` 查看帮助和状态；可用 `o` 查看叠线，`t` 返回文字。`s`/`!` 验证停止响应。

行驶控制仍需真实标定，不能为了连通测试使用虚构的确认值。`a` 不是持续开关：远程运行要持续收到当前控制端 `h`（默认租约 500ms）；帧失效、超时和总时限仍会停机并锁存。无线停止属于软件命令，不是独立硬件断电急停。

## 完全无线选档的建议方案（未实现）

建议新增 `@mode observe|servo|motor|drive`，它应：

- 只由当前控制端提交，模式切换无条件先撤输出，清旧帧资格和分段命令。
- 仅切模式，不隐式 arm、不生成 PWM；随后仍需独立 `a` 或有界点动命令。
- 采用独立的软件模式源，禁止 PIT1 下次采样又用拨码覆盖它。默认上电 OBSERVE，不保存运行授权。
- 控制权切换、停止、接收错误和丢链路不能重放旧启动指令；故障不得因换模式自动清除。
- 增加实际主循环测试，覆盖四档切换、USB/无线归属、STOP 同批优先、碎片行、重连/丢包、错误端口心跳及启动后默认停止。

本次按用户要求只回退按键并评估，不把上述拟议命令伪装成已有功能。现有双串口隔离、路由和实际应用循环回归已经覆盖通信基础；四档纯无线状态机仍需后续实现及实机验收。
