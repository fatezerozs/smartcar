# 单轮起步占空比诊断版

本版本用于比较已成功工程的单轮 `PWM_DUTY_MAX / 5`、1500ms 条件。
20% 是成功工程的工作点，尚不是本车已测得的起步阈值。
本次只生成固件，不自动下载、不自动执行测试。

## 独立构建

在仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_motor_threshold.ps1
```

生成的工程为 `demo/mdk/motor_threshold.uvprojx`，产物为
`.build/motor-threshold/Objects/rt1064.axf`。构建脚本没有下载参数。
正式 `rt1064.uvprojx` 不增加诊断宏，其输出目录不变。

诊断版设置 `VISION_MOTOR_THRESHOLD_DIAG=1`：首次单轮请求最大100‰，
后续每次最多增加10‰，最大200‰，持续时间100～1500ms。
普通版本仍为首次30‰、最大100‰、最长500ms。整车运动上限仍为100‰。
两种版本均保留PIT1到期停止、故障停止、切档停止、两串口停止和2000ms冷却。
诊断版禁止本地自动启动，不执行自动扫描或循环测试；原有串口命令入口保留。

## 手动验证顺序

1. 架空车轮，关闭串口助手的自动发送和HEX发送；115200、8N1。
2. 手动烧录诊断工程并复位后，应看到 `build=MOTOR_THRESHOLD_DIAG_1`。
   发送 `?` 可见 `[THRESHOLD_DIAG]` 和 `max 200 permille / 1500ms`。
   看不到此标识时不要发送扩展参数。
3. 停车后将硬件切到电机档；发送 `t`，确认原始读数
   `[BOARD_IO] C26=1 C27=0 mode=MOTOR ready=1`。
4. 在准备使用的串口发送单字符 `x` 取得控制权，再发送以下整行并附换行：

```text
@motor 0 0 0.1
@wheel 1 100 1 1500
```

第一行只设零巡航和零上限，第二行才触发M1以10%点动1.5秒。
DIR的1只是电平，不等于已经确认前进方向。舵机和另一路电机保持零输出。

5. 确认车轮停止，每两次请求从发送时刻起至少间隔4秒。
   未转动时手动逐次测试110、120……200，每次仍为1500ms，例如：

```text
@wheel 1 110 1 1500
@wheel 1 120 1 1500
```

出现可靠起转即停止增加，记录通道、电平、占空比、电源电压和观察结果。
不要把以上示例设成自动发送。任何时候单字符 `!` 可撤输出。

6. 换M2时从 `@wheel 2 100 1 1500` 开始，两路递增记录独立。
   改DIR前必须确认机械停止；复位会清除递增记录。
   若20% / 1500ms依旧完全无反应，停止提高占空比，转而比较成功工程的
   初始化、引脚复用、PWM输出覆盖和驱动使能条件。

## 离线验证边界

`tests/vision/run_motor_threshold_tests.cmd` 分别编译正式参数和诊断参数，
调用真实驱动、解析器和安全中断函数，使用模拟IO检查输出、递增限制、
到期停止、故障、切档、跨时钟回绕、停止命令和自动启动禁用。
附加 `asan` 可运行地址检查。
这些结果不能证明实体PWM波形或实际起步阈值；后者需要烧录后观察。
