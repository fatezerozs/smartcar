## 工具链与编译

原 Keil 5.28 的 Lite 链接器因代码大小限制无法生成固件。随后从签名有效的 Arm MDK 5.43a 官方安装包独立部署新版工具，按官方命令激活非商业用途的 MDK Community 授权，使用 Arm Compiler for Embedded 6.24 构建；旧版工具保留。

- [Community 授权说明](https://www.keil.arm.com/mdk-community/)
- [官方命令行激活方法](https://learn.arm.com/learning-paths/embedded-and-microcontrollers/vcpkg-tool-installation/licenseactivation/)

工程增加 `-fno-finite-math-only`，保留非有限浮点数的处理语义，解决新版编译器对 SDK 调试控制台 `HUGE_VAL` 使用的两条警告。没有修改视觉控制算法、速度 PI 参数或视觉确认位。早先针对旧版汇编器的预编译启动文件临时方案未纳入本次工程；新版直接编译原启动源码。

## 下载与板端确认

NXP 设备包为 `NXP.MIMXRT1064_DFP.26.09.00`，从工程声明的 NXP 官方地址取得。使用该设备包的 `MIMXRT1064_QSPI_4KB_SEC.FLM`，Flash 起始地址 `0x70000000`，大小 `0x00400000`，算法 RAM 起始地址 `0x20000000`、大小 `0x8000`。CMSIS-DAP 下载器与对应串口均被电脑识别。

最初 SWD 返回 `No ACK`，低速与复位连接均未获得主控响应；用户检查供电并重新插紧排线后连接恢复，读到 DAP IDCODE `0x0BD11477`。错误原因未进一步定性，不将其归因于单一器件。

在驱动板关闭、主板供电的状态下，下载日志依次出现 `Erase Done`、`Programming Done`、`Verify OK` 和 `Application running`。之后出现 `RDDI-DAP Error`：这条末尾错误不能单独作为下载失败或正常运行的结论。随后通过串口确认实际运行标记为 `MIDTERM_TRAIN_1`，相机及编码器采样持续更新，停车状态与电机输出为零；因此本次有写入校验和运行读回两类证据。不要仅凭 Keil 退出码判断现场下载结果。

个人下载器序列号、原始串口日志、照片、安装包、授权缓存及本机 IDE 下载配置不提交。接手者需选择自己的下载器、串口和设备包路径。

## 停车参数恢复

首轮批量配置在途中遇到串口所有权切换，后续指令被拒绝，工具停止发送。随后采用每条指令前重新确认端口所有权的独立恢复流程，逐项检查确认回复，并对最终配置读回进行校验。

可复用入口为 `tools/restore_training_parameters.py`：先安装 `pyserial`，再显式指定实际串口。它只适用于已确认硬件与本次车辆相同的训练基线，使用前保持驱动动力关闭；不是通用车辆参数。

```powershell
python -m pip install pyserial
python tools/restore_training_parameters.py --port COM9
```

工具先停车、核对 `MIDTERM_TRAIN_1`，每条配置前确认 USB 端口所有权；配置确认缺失时至多重试一次相同的幂等指令，固件明确拒绝则退出。结束或异常时尝试发送 STOP 并关闭串口。日志仅写入忽略目录 `.build/field`。不会发送启动、心跳、执行器点动、相机确认或 Flash 保存命令。

| 参数 | 最终读回 |
| --- | --- |
| 自动启动 | 关闭；C12 不作为训练版启动入口 |
| 近带／远带／半带宽 | 0.78／0.62／0.035 |
| 舵机中位／窗口 | 1550 μs／1500～1600 μs |
| 转向映射 sign | -1，按历史脉宽左右映射配置，实际视觉纠偏仍待实测 |
| 电机前进方向／两轮配比 | 1／1；配比 1／1 |
| cruise／cap／rise | 0／0.15／0.1 |
| 运行时限 | 5000 ms，仅供短时训练；整段路线应按实测设置 |
| 编码器方向 | 左 3 为 -1，右 4 为 +1 |
| 速度环 | enabled=1，max_ticks=40，Kp=1，Ki 读回约 0.0469 |
| 输出／故障 | PWM 0／0，faults=0 |
| 相机／整车就绪 | cam=0，ready=0 |

以上现场恢复仅在 RAM 中，未执行 `@save`，复位后不能假定配置仍存在。`@save` 本身也不保存速度环参数。`max_ticks` 是每 10 ms 的编码器计数上限映射，不是已经标定的米每秒车速。

## 验证边界与下一步

本机已通过 `tools/check_arm.ps1` 的 ARM 源码检查和现场协议 23 项检查；新增恢复工具的模拟串口测试不连接车辆。

本次没有发送启动或运行心跳，没有实车直道、弯道或 A—B 全路线通过记录。当前画面为 `NO_LANE`；没有把桌面场景的读数用于参考轴标定。下一步保持主控供电，将车在真实直道上居中摆正，停车采灰度和叠线，确认有效近远采样带并标定参考轴。设置非零低速目标或修改车辆配置后，应重新核对并使能速度环，再进行受控短跑。训练版仍需要显式启动与持续心跳；打开驱动电源或切换 C12 不会启动。
