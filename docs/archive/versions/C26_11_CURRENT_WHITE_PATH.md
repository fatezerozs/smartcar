# MIDTERM_C26_11：依据当前白色通道自主选择方向

2026-10-22。用户反馈C26_10不能正确判断哪边是赛道，要求根据实时白色赛道转向。本次只修改本地代码，不推送GitHub、不自动烧录或驱动车辆。

## 源码核查

C26_10固件中没有按地图固定“先右后左”的运行序列；旧测试文件中的地图场景顺序只属于主机测试，不编入固件。不能据此否认用户看到的实际转向问题。

发现的两个具体机制：左右边线原先分别寻找，可能先命中不同白区，后续才做内部一致性检查；失线阶段则主要沿上一次有效舵量继续寻找，新出现但尚未达到完整帧覆盖要求的反向白色路径不会覆盖旧方向。它们是源码确认的缺点，尚无C26_10本次实车原图/同步日志证明所有现象都只由这两个因素引起。

## 修改

### 当前帧白色通道配对

`vision_reference_route.h/reference_white_corridor`先在当前二值图中选取一段连续白色区域，再取其真实左右边界。沿图像从近到远追踪时，候选白段必须与刚看到的白段重叠或处在有界缺口接续范围内，不把两个分开的白区的左右边界拼成一条赛道。

初始参考是摄像头前方轴线，选择依据来自本帧白区的距离、宽度和行间连接；没有读上一帧转向作为选路依据。暂缺一侧时仍使用本车已成熟的宽度模型补中点，另一侧必须有当前真实边界。不把全白、对称歧义或没有边界的区域自动判作居中赛道。

### 当前白色片段覆盖旧找线方向

`vision_control.c/current_partial_direction`在完整帧无效或近处采样不足时，检查当前56..100行的真实路径结果，至少6个一致性合格的边线/中线行才参与短时方向判断。

- 新片段在左/右时，优先沿新方向打舵，即使它与上次转向相反。
- 新片段居中时回收旧舵量，不强制继续给最小左/右找线舵量。
- 当前片段与旧转向相反时，加快有限速回收，以便在原有短时窗口内改变方向。
- 若前一帧刚将电机需求归零，出现合格新片段后按原加速斜率恢复低速需求，避免只打舵但始终保留零需求。
- 片段仍标记`observation_valid=0`，不伪装成完整有效赛道。不延长最后完整有效路径起算的300ms期限。
- 没有可用新片段时，保留原300ms最近弯向寻找；相机断流不使用此分支。C26 OFF/STOP等仍立即撤销驱动。

串口`[TURN] source=2`表示当前白色片段决定找线方向，`source=1`表示暂无合格新片段、短时使用最近有效弯向，0表示不在找线。完整重新识别后恢复正常实时循迹。

速度保持cruise=.145、cap=.15、rise=.20/s。舵机中位1550us，1490..1610us指令范围不变。未增加地图路线计数或固定左右转程序。
