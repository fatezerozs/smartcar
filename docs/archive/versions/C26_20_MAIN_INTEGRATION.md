# main 赛道合入与舵机/差速联动（2026-10-22）

来源：`origin/debug/c26-20261022` 的 `5125f81`，合入 main 工作区。包含当前白路跟踪、近端居中、单边恢复、十字连接、环岛状态机、C26 启停、运行记录及对应测试。C17/C19 的历史固件和证据原样保留；本次源码版本为 `MIDTERM_C26_20`，不能将历史实测结论直接用于 C20。

## 本次控制变化

- 赛道速度环实际 PWM 上限为 **400‰ = 40%**，参数位于 `demo/code/midterm_route_profile.h` 的 `MT_ROUTE_PWM_CAP_PERMILLE`。这是可用输出余量，并非固定以 40% 运行。
- 原来的 `control.duty_cap=0.18` 保留为速度需求归一化标度：180‰ 需求对应 50 计数/10ms。巡航需求仍为 145‰，长直道约 47 计数/10ms；不会因为提高 PWM 上限而重新缩放目标速度或前馈。`duty` 日志是需求，`pwm_R/L` 才是实际电机占空比（千分比）。
- 40% 仅用于 C26 循迹的闭环运行。独立运动诊断、点动和普通训练的原限制保留。编码器停采、超时、反向及无计数停机继续有效；无计数和反向判据仍按原需求标度设置，没有随着新上限一起放宽。
- 舵机和差速共同使用 `s = u × (2/3 + u²/3)`，其中 u 为限速后的车体转向指令，正值表示右转。舵机保留中心 1550µs、端点 1430–1670µs，以及当前硬件符号 -1。
- 内轮目标比例 `1 - 0.45 × |s|`：直行两轮目标相同，右转降低右轮 M1、左转降低左轮 M2。满舵时内轮目标为外轮的 55%，外轮不额外加速，两轮不反转。左右速度环分别追踪目标，实际 PWM 不必与目标速度保持相同比例。
- 转向混合独立在 `vision_steering.h`，执行器层只应用混合结果。曲线连续对称，沿用视觉控制器的转向变化率限制。该比例是待实车调整的经验参数，尚未标定轴距、轮距及实际转角，不能称为精确阿克曼模型。

## 操作与构建

使用 `demo/mdk/midterm_switch.uvprojx`，目标 `nor_sdram_zf_dtcm`；或执行 `tools/build_midterm.ps1 -Variant switch`。输出为 `.build/midterm-switch/Objects/rt1064.axf`。

C26 OFF 停止电机和舵机输出；ON 且连续五帧有效赛道后开始，C27 忽略。上电已 ON 也会启动，此版本没有三秒倒计时。视觉重获可自动恢复，显式 STOP 后需 OFF→ON；正常循迹没有总时长限制。运行不依赖串口或串口心跳。训练时可被动记录无线日志。

## 验证方案

1. 主机回归：`tests/vision/run_switch_tests.cmd` 与 `asan` 模式。检查灰度→赛道→控制→PWM、左右镜像、混合曲线、低速反馈下输出达到接近 40% 且不越限、速度目标不变、无计数/反向/断帧/STOP/OFF 清零，以及十字和环岛识别。
2. 兼容回归：普通视觉、速度环、原中期启动和手动 route 工程测试。Keil 对 switch 工程全量构建，要求零错误零警告。
3. 实车先核对版本串 `MIDTERM_C26_20`、C26 OFF 零输出及 ON/OFF 启停，再跑短直道、左右弯、连续反向弯，最后十字和环岛。实车操作由操作者进行；本轮未烧录或启动小车。
4. 训练记录重点查看 `command_us`、`target_R/L`、`measured_R/L`、`pwm_R/L`、近远偏差、`ring` 和故障原因。右转应右轮目标较低、左转反之；PWM 永远不超过 400。若弯中持续接近 400 或明显贴边，先降低速度目标并检查舵机端点/机械干涉，再调整差速比例，不能仅继续提高上限。
5. 验收比较同一路段、相近电池状态下的贴边、过弯和停车表现。主机与编译通过只能证明软件约束，不能证明 40% 的实车制动距离、轮胎附着或整圈通过；C19 环岛实车完整验收仍未完成。
