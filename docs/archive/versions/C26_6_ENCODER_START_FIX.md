# MIDTERM_C26_6：实际编码器反向停车与起步响应

## 实机证据与解释

2026-10-21 22:42无线COM15已恢复。板端实际版本MIDTERM_C26_5，servo1550/1500/1600、sign=-1、cruise0.12、cap0.15、rise0.10、40/1/0.0469、sign3=-1/sign4=+1，C26 OFF，主控和帧率正常。首次读取主控刚复位、LAST_STOP=0；不能拿场外NO_LANE作为此前弯道失败原因。抓到的94x60预览是场外地面，不是弯道原图。

随后取得保留记录（serial-20261021-224828-037.log及serial-20261021-225001-431.log）：

LAST_STOP seq=7 ms=356157 run_ms=61 reason=2 faults=256 speed_detail=8。

256为VC_FAULT_ENCODER，8为VS_FAULT_REVERSE_RIGHT，证明这次运行在启动61ms后由右轮反向判定撤销驱动。用户观察前轮先正确偏转再回正、电机不继续，与驱动被撤销相符。原始故障瞬间计数未被C26_5留存，当前残留measured_R/L=-2/-1和总累计计数不等于故障采样，不能证明编码器接线必错或判定必为噪声；不得盲目翻转符号。

## 修改

1. C26候选反向判断：短时1..2计数且很低驱动需求不再立即计为真实反转。较快路径要求目标至少3计数/10ms、上一输出至少cap/4、反馈<-2，连续30ms触发。小负计数在至少cap/2驱动下持续200ms仍触发；没有移除真实反转保护。非C26版本保留旧策略。
2. 速度PI加入目标比例前馈ff=target*cap/max_ticks，PI根据测量误差修正，积分抗饱和计入前馈，零目标/STOP/无效采样仍清零。前馈不是固定起步冲击，不扩大15%输出上限；原ws_pi_step以前馈0调用，旧目标行为兼容。
3. C26候选cruise0.145、rise0.20/s，有效弯道目标下限cruise*0.45（约17计数/10ms），无有效视觉仍零输出。该值是待实车验证的候选，不是已经达到的速度。
4. 根据新证据用户前轮本已可正确偏转，撤回尚未交付的扩大窗口尝试；最终舵机仍1500..1600/1550/sign=-1，转向预瞄和单边模型保持。
5. 修复STOP/串口查询发生在C26已稳定OFF时，下一次ON被旧operator_stop锁挡住的问题。明确ON时发出的串口STOP仍有效，直到OFF确认后才解除。
6. C26版本上电默认无线为日志owner，不必先发停止/claim才能收运行数据。其他目标仍默认USB。
7. trip在清输出前保存原始raw3/raw4、上一目标、上一PWM；LAST_STOP跨OFF保留这些字段，便于判别毛刺与真正反转。主控复位仍会清除，因此下次问题发生后保持供电不复位。

本轮没有通过串口启动或驱动车辆；已向用户解释测试是摆直道后C26启动自动驶入弯道，不是用手推车或手控转向。用户烧录前继续保持C26 OFF、驱动关闭。
