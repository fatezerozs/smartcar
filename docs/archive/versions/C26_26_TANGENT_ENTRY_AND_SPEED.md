# C26_26：相切圆环切入与继续提速

本轮对应操作者反馈“有明显改进，但速度仍慢、右侧与直道相切的圆环未切入”，以及随后“继续提速”。目标仍按不出界、岔路延续方向、尽可能覆盖全部赛道、尽可能快完成的顺序，同时考察局部和整程的速度、稳定性。训练阶段无线可用时直接监听，视频与日志共同作为现场依据。

## 现场依据与边界

已解码并查看 `C:/download_temp/VID_20261022_191838.mp4`：1080×1920、30fps、949帧，时长约31.63s。先按2秒抽帧，再补看奇数秒及30.5、31、31.6秒，另检查12、14、26、30秒原尺寸画面。可见连续弯道、直线和末端十字，末端十字附近推进偏慢；视频有跟拍、遮挡和短暂离开画面的情况，不能据抽帧宣布全程无停车/无出界。未取得完整、明确对应右侧相切圆环进出的连续画面，该问题结合操作者指认与代码回归处理，不把视频当作算法状态证据。

## 相切圆环：识别之外增加入口路径

旧透视回归只覆盖24组较窄的投影。扩大到40组、行90宽度可到151–173像素后，复现出12组“进入圆环状态，但所选道路误差仍接近直线”的失败；相应场景的最大方向偏移仅约1.85–2.86像素。失败记录为 `.build/c26-26-red-projection.log`。这支持检查“识别到了却缺少切入路径”的机制，但没有本次车载图像，不能断言它是实车唯一原因。

新增独立模块 `vision_ring_entry.h`：

- 只有ENTER且**当前帧仍检测到同侧岛形**时才产生入口目标；单独保留ENTER状态不能继续提供引导。
- 目标在当前测得的道路中心基础上向岛侧偏移，最多为道路宽度18%；当前岛形下缘越接近车辆，入口目标越延伸到近处。不是定时打舵，也不按固定赛道位置触发。
- 候选周围至少半个道路宽度的中央条带必须全为当前白色，原中线到候选的横向过渡也必须为白色；至少12行支持。不通过时取消引导。
- 测得边界、道路宽度和普通中心线不变；入口目标另存 `entry_guide[]`，不会学进宽度模型。`raw_error_px` 保留普通道路中心误差，`error_px` 报告所选导航目标。
- 控制器仅在通过原边界检查的行上采用入口目标；完整十字桥接行不被入口偏移替换。转入FOLLOW后由实际圆环边缘继续控制，入口偏移撤销。

在宽度151像素的左右镜像透视场景中，灰度→实际控制器→舵机输出回归均出现116个有引导的有效控制观察，朝岛侧舵量峰值约0.708/0.738。40组场景全部通过，逐行核对引导条带的白色余量。场景相机位姿故意沿直线推进，没有车辆动力学，不能用这些结果宣称实车已经绕完圆环。

## 速度与差速

清晰道路速度标度从C25的84提高到132，清晰双边弯道72→104，持续当前单边线64→92；基础50保持。单位均为计数/10ms，实际目标还受控制需求、转向差速和道路证据限制。舵机仍使用操作者确认的右1430、中1550、左1670µs，sign=-1。

清晰居中直道的额外提速确认从400ms缩短到200ms；确认后的共同轮速目标每10ms最多增加2计数，弯道快档每10ms增加1计数。较弱道路、反向弯切换、十字/入口过渡仍依照当前证据降低速度。动力PI继续按需输出，每10ms最多增加10‰，最终PWM物理范围0–1000‰；没有恢复固定40%限制。

提速回归还暴露了独立轮速爬升的问题：在转弯启动/加速早期，两轮各自限速会暂时得到相同目标，抵消部分前轮转向。新增 `vision_wheel_targets.h`，先限制共同速度包络，再按**当前转向所需比例**分配左右目标；该比例不再在加速阶段被独立爬升抹平。内轮随有界舵量变化调整，不宣称每个内轮目标变化都受共同包络的单独斜率约束。降低目标仍及时执行，前馈有符号补偿及编码器保护保留。

最终回归的目标/模拟反馈如下，不是实车速度：

| 场景 | C25目标 | C26目标 |
| --- | --- | --- |
| 清晰直道，右/左 | 77/78 | 122/123 |
| 右弯，右内/左外 | 33/50 | 47/73 |
| 持续单边满舵，外/内 | 35/22–23 | 50–51/32–33 |

这些是特定模拟场景的命令对比，不能当作实车提速百分比。轮径、传动比及有效每轮计数仍未完整标定，因此不换算m/s。

## 现场验证入口

使用 `demo/mdk/competition/midterm_switch.uvprojx`、目标 `nor_sdram_zf_dtcm`，确认版本 `MIDTERM_C26_26`。烧录前C26 OFF；ON且连续五帧有效道路后启动，上电已ON也可能启动。构建不等于已烧录。

先在同一短直道和左右弯比较实际反馈与目标、目标切换后的超调、出界与停车；再以同样接近方向验证右侧相切圆环。观察：

- `ring=0`：尚未识别/已经取消，需要入口图像证据。
- `ring=1 entry_guide>0`：当前有通过白色余量检查的入口目标，应结合 `u`、`command_us`、实测轮速检查是否实际转入。
- `ring=1 entry_guide=0`：当前岛形或白色余量不足，不能通过继续加速代替识别。
- `ring=2`：进入同侧跟随，仍须视频确认实际走线；状态值不代表已绕一圈。

`entry_guide` 行数加入实时文字与TRACE，离线CSV导出也保留该字段。无线可打开时按115200/8N1、DTR/RTS关闭直接只读接收；串口被其它应用占用时不强制关闭应用。结束后C26 OFF并留出完整TRACE导出时间。视频、MCU时钟与主机接收时间未经同步时分别记录，先以共同事件核对，再比较同路段速度与稳定性。

局部通过后才组合整程，记录完整覆盖成功次数/尝试次数、出界、异常停车与位置、轮速分布及行驶时间。停车扣除时间但仍记故障；新增入口偏移不能独立保证全赛道覆盖。

本轮视频原画面已检查、元数据和软件回归为computed；串口原件与CSV/JSON为结构解析依据。没有使用md_extracted推导机械角度、车速或完整赛程。尚无C26真实移动试跑和完整圆环/全程验收记录。
