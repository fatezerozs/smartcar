# C26_23：实车日志驱动的速度与路径修正

当前目标依次为：不驶出赛道；岔路优先延续当前方向；尽可能覆盖全部赛道；尽可能快完成。验收同时考察局部和全程的**速度、稳定性**。40% 电机占空比、1430–1670μs 舵机窗口、舵机与差速的组合均不是赛题约束，可以随验证结果调整。

## 本轮依据及尚未确认的部分

已复核操作者给出的 `3fa4d2ce454d3ae912e87d41f1a0a80e.mp4`。解码结果为720×1280、30fps、1564帧、约52.13秒；按秒查看原画面，另查看22、49、51秒原尺寸帧。可观察直道、连续弯、十字与回环的通过过程，以及末段弯道推进缓慢；抽帧不能证明每一时刻都未出界，也不能单独确定各次停车的固件原因。

同时读取 `recordings/seekfree-20261022-175957-063267/session.log` 与其原始字节归档。原件 SHA256：`204fe21b6df89573f19e13f84adc12013e41dc2d2dfb852686f7b782778bd894`。日志版本明确为 C22，存在复位后的多个时钟段；没有可靠的视频—MCU同步，因此没有把视频秒数强行对应为某条 LAST_STOP 的时间。

代码与日志能支持的结论：

- 部分持续弯道双边行仅5–8行，但当前单边行达到60–79行，行90参考宽度约144像素。旧快档要求双边，导致这类道路被持续限制在基础轮速档。尾部 TRACE 可见外/内轮目标约28–30/18–19计数/10ms。这说明存在主动限速，不能只归因为电机缺少驱动力。
- 存在 `faults=2` 的视觉停车；其中可见 `ring=1` 但选出道路行不足。没有当时相机原图，不能确定都是圆环误识别。代码上确有“圆环意图覆盖普通路径”的风险，因此加入路径可行性比较，并通过公开视觉 API 的透视场景验证。
- 另有 `no_count_right`、`reverse_right`。前者快照中左右计数都接近0，后者出现右轮负计数；当时是否架空、驱动断电或人为推动车辆未知。没有通过放宽编码器保护掩盖这些现象。
- 大量满舵样本说明需要检查机械转向余量；它本身不证明转向符号错误。当前没有机械转角或舵机堵转反馈，扩大脉宽等待操作者测试结果。

## 修改内容

### 1. 速度请求与动力输出分开调整

道路速度标度集中在 `midterm_route_profile.h`：基础50不变，清晰道路68→84，清晰弯道60→72，新增当前单边线64，单位为计数/10ms。它们是归一化需求对应的目标标度，不代表每个场景都要求该数值，也不是m/s。

`speed_mode=3` 需要同一侧至少28个当前真实边缘行、其中连续至少20行，并延伸到近端98行以上及远端68行以下；行中心须符合已学习宽度与当前边缘。另要求质量≥60、近远端有效、近端偏差<0.45、舵机命令已接近当前目标、没有十字桥接及明显反向弯冲突。少量零散边缘、纯历史宽度或无边界画面不得启用。

清晰直道和双边弯道按新标度增加目标；当前单边弯道也不再仅因缺少另一侧边缘而被一律压低。偏移较大、预瞄不明确、反向弯切换和岔路仍由当前控制误差降低速度。

取消闭环行驶的固定400‰输出限制。`vision_power.h` 根据各轮**上一次实际输出**提供下一次 PI 可用输出边界，每10ms允许上升10‰，最终只受PWM物理范围0–1000‰约束。PI使用该动态边界执行抗积分饱和；目标下降、超速纠偏和STOP不受这条上升斜率限制。没有强制最低占空比，也没有把前馈随100%输出范围同比放大；前馈仍以180‰/50计数为暂定关系。

该修改允许速度误差持续存在时使用40%以上的动力，同时避免突然跳到大占空比。它不保证电机在任意负载下都能达到目标。反向、无计数、采样间隔、控制超时及断帧保护保留；独立点动/运动诊断的原有限制不变。

### 2. 圆环判断不能丢弃仍然可用的当前道路

`vision_route_path.h` 检查当前道路行的白色覆盖、宽度、纵向延伸和锚点。圆环ENTER/FOLLOW提出的新路径不足以控制，而普通路径仍可用时，选回普通路径并标记 `path_fallback=1`。ENTER立即推迟；FOLLOW连续3帧无可用圆环路径则解除该状态。

回退所用的是**同一帧**可见的边缘/白色通道，不能凭历史方向盲冲。两条路径都不足、全白无锚点、全黑或断帧时仍撤销动力。十字入口方向优先与已确认圆环的同侧跟随保留；这不是完整赛道覆盖或整圈绕岛的证明。

### 3. 舵机标定值可以替换

中心、左右窗口集中为 `MT_ROUTE_SERVO_CENTER_US / MIN_US / MAX_US`，不再作为不可变行驶目标。当前默认仍为1550、1430、1670μs，等待操作者提供更大机械安全行程的实测结果。软件合法脉宽范围不等于连杆的安全范围，无法靠编码器判断舵机是否顶死。

左右轮差速方向和舵机转向符号保持一致；现有满舵内轮约65%的混合先作为可比较基线保留，不宣称它是最终最优方案。

## 可重复的局部回归

新增与现场宽度相近的灰度图：先学习 `width=54+y` 的直道，再左右镜像裁掉一侧边缘，连续经过实际阈值、路径、控制、轮速PI及模拟PWM输出。两方向均得到87行当前单边线，并持续运行；外/内轮目标为35/22–23，启用 `speed_mode=3`。这只是测试场景，不能与未同步现场日志直接计算实车提速百分比。

双边满舵回归的外/内轮目标为50–51/33；清晰长直道目标至少75且不超过84。高负载模拟可超过40%并接近PWM满量程，逐样本核对功率上升斜率；OFF仍立即归零。碎片边缘和无路图像不能继承快档。

24组透视/镜像场景触发12次当前道路回退，逐次检查回退结果有效、输出中线仍落在当前白色像素内。原十字、圆环进入/退出、黑带、全白、曝光丢失、重获、反向/无计数及应用层回归继续运行。这里没有真实车身动力学，不能证明高速不出界。

## 上车验证

使用 `demo/mdk/competition/midterm_switch.uvprojx`，版本应为 `MIDTERM_C26_23`。C26 OFF停止；ON且连续五帧有效道路后启动，上电已经ON也可能启动，无三秒倒计时。没有代替操作者烧录或发车。

1. 先检查刚测得的机械转向范围，再按需要更新上述标定值。左右都应无机械卡死，并保留实测脉宽记录。
2. 同一段直道、左右弯和十字分别重复测试，建议每种至少3次。核对实际轮速、目标误差、出界/触线、异常停车、恢复次数；不能只报告一次最高轮速。
3. 核对 `speed_mode`：清晰双边道路1、双边弯道2、满足条件的当前单边3；观察 `[SPEED]` 输出是否按需超过400‰、是否存在持续超调或左右反馈异常。`[TURN] command_us` 是命令值而非实际转角。
4. 路口观察是否沿入口方向通过、是否出现 `path_fallback=1`、回退后是否仍有足够当前道路。若无图像证据仍停车，保留图传/视频，不继续扩大盲行时间。
5. 逐步组合到完整路线，报告成功完成次数/总尝试次数、出界次数、故障停车次数与位置、覆盖遗漏、同路段轮速分布及整程行驶时间。停车时间按原约定扣除，但全部停车仍作为故障。速度数据不能替代路线稳定性。

训练阶段允许无线串口采集；正常循迹及启停不依赖串口指令或心跳。终止后C26保持OFF并等待匹配TRACE_END，避免短暂停车的未完整导出被当成完整记录。

源码/日志直接阅读、日志字段解析及原视频画面核对为本轮依据，视频时长与软件回归为computed；没有仅用文档概述证明数值、机械范围或实车成功。当前仍缺C23真实局部/整程对照、视频时钟同步、机械转向测量、完整路段覆盖证据。
