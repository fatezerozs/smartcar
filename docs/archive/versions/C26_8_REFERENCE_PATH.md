## 使用用户提供的参考源码

源文件保存在 `.build/reference-review/newnew/IMG_DEAL.c` 和 `main.c`，对应用户提供的 `newnew.zip`，源码映射见同目录上层 `source-map.json`。

- `LeftStartFind/RightStartFind`、`left_jump/right_jump`：左右边线分别寻找起点和逐行连续搜索，每侧允许每行约10像素的搜索变化。改写为有界数组索引、独立缺口处理和最近候选选择。
- `fixpoint`：用边线之间的当前白色内部一致性检查，拒绝跨越明显暗区的错误配对。
- `Racing_Line`：有两侧时取中线；一侧暂失时沿另一侧加减半宽。没有照搬对方摄像头的 `TrackWild[]`，使用本车多帧实测的逐行宽度；当前帧必须仍有连续边线，且模型内部大部分是白色。
- `main.c/ImgDeal_GetMidError`：采用可见多行中线加权，而不只依赖两个固定行带。保留现有本车轴线校准、舵机方向、PWM与编码器驱动。
- 没有移入参考项目的环岛、斑马线、显示屏、硬件管脚、像素宽度表和速度标度。

实现位于 `demo/code/vision_reference_route.h`（由视觉模块私有包含）和 `vision_control.c`。仅 C26 构建采用新视觉流程；普通固件原流程保留。

## 控制行为

1. C26 ON、摄像头与启动条件成立后循迹；C27忽略。
2. 左右边线独立跟踪，一侧消失不再同时切断另一侧。只剩较远的有效中线时，可把近处采样带移到当前真正可见的路径。
3. 前方40..88行中线参与加权预瞄，提前生成弯道指令。
4. 正在运行且刚刚有明确弯道指令（绝对值>=0.12）时，短暂丢线进入循弯找线。沿该方向将舵量目标至少推至0.60，仍受原舵机1500..1600us及转向变化速率限制。电机目标限制在现有巡航目标的45%以内。绝不伪报视觉有效。
5. 找线从最后一帧有效路径起最多300ms。期间找回有效路径立即恢复循迹；超时停车并等待重新识别。启动时没有赛道、只有直道历史、相机帧停止均不会据此盲目转弯。
6. C26 OFF、显式STOP、编码器异常及原有运行时间限制仍生效；OFF在硬件10ms采样路径中停止输出。

当前用户认可的速度配置保持 cruise=.145、cap=.15、rise=.20/s、max_ticks=40/10ms，速度环与硬件映射没有改动。程序中已经去掉 C26 大偏差 OFFSET 的旧硬停，本次没有继续扩大舵机机械范围。

串口 `[TURN] search=1` 表示正在短时循弯找线，`near_valid=0`时仍明确标记无有效路径。
