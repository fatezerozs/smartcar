## 安全默认值与范围

当前默认只采集和识别。原主程序整车时序逻辑已移除，可从 Git 历史对照；PIT0 仅清标志，不读取编码器或写 PWM。两条新路径见 [BAYES_REFACTOR](BAYES_REFACTOR.md)。

相机闭环的是横向转向：实测中线相对标定参考轴的误差除以实测半路宽，结合近远差和按实际帧间隔计算的滤波 PD。电机只有开环占空比限幅和变化率限制，**没有实际速度反馈**。

默认 enable、硬件确认、相机标定均为 0，舵机端点及电机占空比均为未配置值 0。测试脚本中的示例脉宽/占空比仅是模拟编译参数，不写入工程配置，不得照抄到实车。

识别失效、帧/控制/指令超时、运行时长上限、非法数值等会锁存故障并撤销输出；恢复图像不会自动启动。PIT1 不等于独立硬件看门狗，也不能处理关中断卡死。现有硬件没有确认可采集的电流、驱动故障和电池电压反馈，不能宣称已实现堵转/过流/低压检测。详细标定和启用前检查见 [VISION_CONTROL](../demo/code/VISION_CONTROL.md)。

## 构建、下载和验证

使用 Keil GUI：打开指定工程，核对目标与编译器，Rebuild all target files，检查新生成目标和构建时间。Keil/设备包是外部工具依赖。`Objects` 不随项目提交；第一次打开时必须构建。

本次发布不执行 Download，不替用户重新选择硬件供电/引脚，不要求现在再回场地。今后下载前保持电机安全隔离，确认供电及下载器接线，编译成功后使用既有已验证流程。看到 `Verify OK` 后又有 `RDDI-DAP Error`，应区分写入校验与后续调试连接失败，不能仅凭最后一行确认程序已正常运行。

开发者可运行 tests/vision/README 中的命令；这些不是要求初学者必须用终端操作。验证脚本只编译/测试，不烧录。测试输出和临时文件自动留在忽略目录中。最新实际结果单列于 [VERIFICATION](VERIFICATION.md)，不以旧固件产物冒充新构建。
