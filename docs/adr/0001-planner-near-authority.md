# 规划器近场判断与转向控制的职责

针对 `METRIC_EXPERIMENT_20261111_4` 所代表的米制 CONTROL 链路，先保留现有转向算法，优先统一规划器近场判断的使用权、启动准入顺序与最终输出职责；有效转角模型及舵机标定映射在后续步骤完善。用户已确认这一推进方向。本决策描述目标架构，不表示源码已修改、构建通过或实车验收完成。

米制 CONTROL 的道路近场有效性以规划器近场预瞄判断为准。旧控制器近场判断不再作为重复的道路有效性否决来源。规划器结果缺失、过期、版本不匹配或不可用不能解释为准入；硬 STOP、严重故障、数值检查及输出授权保持独立约束。近场道路有效也不等于转向候选必然可用，两者需要分别表达。

选择保留现有转向，是为了先消除道路判断、启动和最终输出之间的职责交叉，再单独验证物理转角模型的变化。转向和速度应能关联到明确的帧号、采集时间和路径版本；二者允许使用各自所需的有效视野。规划器和转向控制均只生成候选，执行器由统一输出层提交。

首次启动要求同时具备新鲜的规划器近场与完整预瞄，以及编码器、硬件、配置和输出授权等前置条件。启动后完整预瞄丢失，才进入既定时间/距离预算约束下的近场降级。用户已确认保留这一首次启动条件。

用户未接受“转向候选短暂不可用就立即清零双轮动力”的提案，要求区分短时间波动。针对规划器近场有效、转向候选波动的情况，用户已逐项确认：

- 短暂无更新或单个候选被拒绝、上一有效转向仍可信时，延续仍有效的转向，保留 PI 状态，限制加速，不因该事件直接清零动力。
- 波动持续、可信路径和转向余量减少时，由同一规划层收紧速度上限并平滑减速，避免各层重复降速。
- 新候选恢复可靠时，平滑接回并逐步恢复加速能力，不重置整次运行。

用户选择同时重设计停止的判定条件与停止方式，并已确认以下原则：

- 综合当前路径、历史路径剩余覆盖、转向变化和运动反馈收紧允许速度；单次候选失败或丢帧数仅作为证据，不直接产生停车命令。
- 普通证据不足时优先降低速度参考，由原双轮 PI 跟踪减速直至零速，保留仍可信的转向引导；过程中不因普通波动直接清空 PI 或撤销授权，也不能为了平滑而超出剩余可控边界。

是否维持当前速度参考取决于综合约束，不应将短时波动一概解释为维持原速或一概解释为立即降速。既有显式 STOP、严重故障及输出授权约束保持独立；真正规划器近场无效的原有规则不在此次转向候选波动讨论中顺带变更。

用户已确认：上述普通转向证据不足导致受控减速并停稳后，进入保留本次运行授权的“零速等待恢复”，不因本次软停止直接锁止整次运行。等待期间保持零速度目标；新鲜近场、完整预瞄、有效转向及其他准入条件重新满足后，平滑起步。旧帧不能刷新恢复证据；显式 STOP、物理撤权和严重故障仍按各自规则锁止，不得由视觉恢复清除。

这是对本类普通证据不足停止方式的明确设计变更，应与终止运行的 STOP_LATCHED/FAULT_LATCHED 区分。它不自动取消原有远场累计预算、帧新鲜度或其他独立停止条件；恢复前仍须检查这些条件，不能通过软停止或恢复重入重置未满足退出条件的预算。设计范围与后续验证见[设计共识](../changes/planner-authority-design-20261111/README.md)。

可信延续、约束收紧与恢复的具体算法及生产参数尚未实施或验证，不应写成现有实车能力。[既有连续降级设计](../changes/soft-degradation-events-20261109/SOFT_DEGRADATION_PLAN.md)已提出证据减少时降低可用能力、坏候选可隔离时不直接终止会话，后续方案应与之对齐。
