# C26_22：弯道驱动力与十字过渡

实车反馈：C21 直线改善，但弯道慢且有时停止，进入十字仍会停车。本轮修正代码中可重现的问题；没有 C21 实车停止快照，不能认定每次停车都属于相同原因。现有 `LAST_STOP`、`SPEED_FAULT` 与 TRACE 继续用于区分视觉、编码器和断帧故障。本轮不修改新加入的录制/日志导入工具，也不自动操作实车。

## 舵机和差速检查

源码映射和镜像测试一致：M1 是右轮、M2 是左轮；车体正舵量右转，右轮目标较低，舵机按硬件符号 -1 输出。中心 1550µs，右转端点 1430µs、左转端点 1670µs。未发现左右轮或转向符号写反；本轮没有测量实际机械转角。

C21 的问题是降速叠加：舵量超过 0.8 会退出快档，而满舵内轮又只剩外轮的 55%。C22 改为共用原渐进舵量的差速曲线、满舵内轮 **65%**，保留外轮不额外加速、两轮不反转、转向变化率及所有输出限幅。这是待实测的经验混合，不能替代按轴距、轮距和实际转角标定。

## 速度与 PI

`speed_mode` 为 0 基础标度50、1 清晰道路标度68、2 清晰弯道标度60，单位均是计数/10ms。直线的 C21 提速逻辑保留。

当前远端可用、覆盖至少65%、实测双边至少20行、近端误差小于0.40、舵量至少0.45且已接近当前目标时，可进入弯道档；满舵不再自动失去该档位。反向弯切换、缺远端、单边估计或明显偏移继续限制速度。清晰居中弯道的共同需求可达巡航的90%，弱证据降到50%–60%；实际电机 PWM 上限始终 **40%**。

按相同标定和理想清晰满舵场景，C21 的外/内轮目标约29/16，C22 约 **43/28计数/10ms**，前馈相应约15.4%/10.0%，再由各轮 PI 修正。这些是计算/模拟目标，不是实车速度或固定占空比。目标加速仍逐10ms样本限速；弯道目标、PI和40%硬上限分别承担速度请求、反馈纠偏和输出限制。

修复 PI 积分问题：C21 对每一次目标下降都按比例削减积分，一计数的反复波动也会反复损失驱动力。C22 仅当目标下降至少25%且至少3计数时执行积分跟踪，小幅波动交给 PI 自身处理。这样保留进入路口时的大幅降速响应，减少连续弯里积分被反复削弱。反向、无计数、采样/控制超时保护未放宽。

## 十字过渡

1. 出口从“八行必须完全连续”改为“最多十行内八行当前实测锚点”。最多两个边缘缺失行必须仍能通过当前白色道路检查；横向黑带不能跨越，计数仍报告实际八行，不把缺失行当实测。
2. 取消“底部六行仍窄就跳过出口搜索”的提前返回。改为先检查是否存在当前扩展白区，普通道路快速退出，避免增加无意义的重计算。
3. 新增四行短入口过渡：必须有当前四行窄入口、最近已建立的方向，以及前方至少十二行扩展白色通道。标记 `junction_partial=1`、`anchors=4`、`valid=0`，只帮助已经运行的控制器低速前进，不能自动发车，也不刷新完整有效帧时间。
4. 这类部分十字只沿当前入口方向指导，不叠加旧弯道残留舵量；需求上限为巡航60%，低于清晰道路和弯道。旧方向参考失效、黑带或当前边界完全消失仍撤销动力。正常退出到有足够当前锚点的十字/道路后再恢复正常控制。

这解决的是短入口和断续出口证据的衔接，不是让车辆在一片无边界全白画面里盲冲。全白无锚点、全黑、断帧及显式 OFF/STOP 仍走原停车路径。环岛状态机保留，完整环岛和全赛道覆盖仍须实车验证。

## 验证与使用

版本 `MIDTERM_C26_22`，使用 `demo/mdk/midterm_switch.uvprojx`，构建命令 `tools/build_midterm.ps1 -Variant switch`。C26 OFF 停止，ON 连续五帧有效赛道后启动；上电已 ON 也可能启动，无三秒倒计时。本轮只生成固件，不烧录或启动。

新增测试包括：左右镜像满舵弯的舵机端点/轮速方向/65%内轮目标；加载模拟下反复一计数目标波动仍保留 PI 驱动力；四行入口不断行但不得发车、不得刷新完整有效时间、不得无限保持；过渡到完整出口；出口边缘闪烁；黑色断带与全白拒绝。测试使用真实视觉/控制/速度环代码和模拟硬件，不是实车动力学证明。

实车优先对比同一弯道两方向，记录 `speed_mode`、`u`、`command_us`、左右目标/实测轮速和 PWM。若再次停止，结合 `LAST_STOP` 与 `SPEED_FAULT detail` 判断：VISION 是当前道路证据不足，FRAME 是断帧，ENCODER 需继续区分反向、无计数或采样间隔。不能只凭“停下了”就继续放宽保护。

阅读层为原始 C/H、Markdown 与工程 XML（structured_parsed），编译和回归为 computed。本轮没有新的实车日志或实测占空比；原因分析中哪些可在代码重现、哪些仍待实车确认已分别注明。

## 本轮验证结果

switch 优化回归通过；最终 ASAN 套件通过，包括完整应用、灰度到执行器286588项、环岛238项及24组地图透视/镜像1203项。普通视觉、速度环、中期启动和手动 route 兼容回归全部通过。模拟测试包含2000次目标抖动和满舵左右转、短入口过渡与超时停机，不代表真实车辆已完成赛道验收。

Keil switch 全量构建：0 Error(s), 0 Warning(s)，Code 83896、RO-data 13180、RW-data 212、ZI-data 196476 字节。输出 `.build/midterm-switch/Objects/rt1064.axf`；日志位于 `.build/c26-22-asan.log`、`.build/c26-22-host.log` 和 `.build/c26-22-run_*.log`。
