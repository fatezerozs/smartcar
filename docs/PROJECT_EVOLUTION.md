## 1. 成品目标与优先顺序

成品应能上电后确认正确赛道再行驶，稳定处理直道、弯道、十字和相切圆环，完成规定路段；
训练时有足够信息定位问题，正式运行不依赖串口指令。

目标顺序由操作者确定：

1. 不能驶出赛道。
2. 面对岔路倾向保持当前方向；该偏好不能成为漏掉必须覆盖路段的理由。
3. 倾向跑完所有赛道，包括目前仍未进入的右侧相切圆环。
4. 在前三项满足的前提下尽可能快完成全程。

行驶时间排除经核对的停车时段，但每次异常停车都记为待解决故障，不能靠扣除停车获得虚假成绩。
计时边界由日志与可用视频核对，没有采用未经确认的固定 A→A 规则。
见 [速度与稳定性验收](reference/TRACK_TIME_ACCEPTANCE.md)。

## 3. 当前模型与技术路线

### 3.1 运行链路和模块边界

```text
摄像头当前帧 → 自适应二值化 → 当前连通白色通道/边界
             → 十字连接与圆环几何阶段 → 近远偏差/入口引导
             → 视觉转向及连续道路支持 → 左右轮目标
             → 编码器 PI + 前馈修正 → PWM 与舵机
```

贝叶斯是并行估计路径；保护检查可以撤销输出。训练通信不能成为正常循迹的必要心跳。

| 模块 | 主要职责 | 职责边界 |
| --- | --- | --- |
| `app_runtime.c`、`vision_frame.c` | 调度、一致当前帧、调用估计/控制、安排遥测 | 不堆入赛道补线或逐轮 PI |
| `vision_midterm.c` | 二值化、结果发布、宽度学习与视觉生命周期 | 不直接操作电机 |
| `vision_reference_route.h` | 当前通道、内岛识别、圆环阶段和路径发布 | 不用固定行驶秒数替代几何证据 |
| `vision_route_junction.h`、`vision_route_path.h` | 当前白色桥接、真实锚点和路径可行性 | 不凭历史方向生成不存在的道路 |
| `vision_ring_entry.h` | 当前白色余量内的入口引导 | 不污染真实边界或宣称已绕完圆环 |
| `vision_control.c`、`vision_junction_policy.h` | 近远控制、转向变化和几何支持度 | 不把道路名称或未校准概率当作速度极限 |
| `vision_wheel_targets.h`、`vision_speed.c`、`wheel_speed.c` | 连续目标尺度、共同包络、采样、PI/前馈 | 不替代导航或覆盖判断 |
| `vision_steering.h`、`vision_actuator.c` | 同源舵机/差速映射、输出适配 | 不重做视觉分类 |
| `vision_drive.c`、`vision_guard.c`、`vision_startup.c` | 配置、生命周期、记录和保护协调 | 不继续吸收所有几何、规划和估计算法 |
| `track_bayes.c` | 特征、后验、拒识和受约束入口提示 | 不直接覆盖像素证据或输出 PWM |
| `app_link.c`、`app_transport.c`、`vision_telemetry.c` | 队列、所有权、协议和诊断 | 不让训练通信阻塞循迹 |

私有头文件是当前 C 模块内部的拆分形式，不代表独立任务或额外硬件线程。
新增职责按功能归属，避免重新形成包揽所有功能的驱动文件。

### 3.2 道路和圆环模型

当前处理尺寸为 188×120。参考场景为亮色道路和较暗外侧，以当前二值图中的连通白色通道选择路径。
真实双边、当前单边加已学习宽度、当前白色验证过的桥接分别标记；覆盖率不是识别正确概率。
它不是语义分割网络，也没有完整相机外参或车辆动力学校准。

十字倾向延续进入方向，仍需当前锚点和白色通道。
圆环使用空闲、进入、跟随、退出、冷却阶段，入口引导受当前白色余量约束。
C30 用外边界全部有效点拟合，减少首尾量化造成的漏检；C31 对已经确认、同侧、接近 ROI 下端的内岛，
允许用符合空间匹配的当前截断轮廓延续引导，避免接近切入时引导突然消失。
软件修正已有回归，仍未证明实车能驶入右侧相切圆环。

### 3.3 控制与速度模型

近端横向误差、远端预瞄和变化项形成转向请求，经速率约束后共同驱动舵机和内外轮差速。
逐轮采用编码器反馈、PI 与可有符号抵消的前馈修正；两轮 PWM 不必相同，PWM 也不是速度。
没有实测转角反馈或完整轴距/轮距模型，不将当前联动称为精确阿克曼控制。

| 参数/量 | 当前值或解释 |
| --- | --- |
| 轮速单位 | counts/10ms；未完整标定为 m/s |
| 需求尺度 | base 50、edge 92、corner 104、fast 132；C29 起按当前支持度连续混合 |
| 动力范围 | 循迹 PI 按需在 PWM 物理范围 0–1000‰ 输出，已取消历史固定 40% 上限 |
| 动力上升率 | 每 10ms 样本最多增加 10‰，与轮速目标包络是不同层级 |
| 舵机静态标定 | 右 1430µs、中 1550µs、左 1670µs；正车体右转对应较小脉宽 |
| 电机载波配置 | 17kHz；尚无示波器确认真实波形，不能认定为迟滞根因 |
| 舵机频率配置 | 50Hz；不能与电机载波或闭环更新周期混淆 |

双边支持量连续变化，单边支持结合数量、连续长度和近远覆盖。
共同目标包络保留差速比例，诊断标签不再直接切换速度尺度。
这些已减少可复现的跳变，但实车仍有卡顿：还需核对远端有效性、部分恢复、转向请求、PI 输出及帧/通信间隔。

限速必须谨慎，不能仅因“路口/圆环/弯道”标签统一爬行。
需要对应实际路径余量、偏移、跟随失配、出界趋势或其他目标受损的证据；正常目标变化尽量连续。
现有尺度仍是待验证调参，不是已测物理极限。平滑不能延迟明确停车和故障撤输出，也不能掩盖识别错误。

### 3.4 贝叶斯的实际接入程度

已有隐状态包括 UNKNOWN、直道、左右弯、十字、斑马线和左右环岛进入/环内/退出。
六类特征及缺失 mask 进入似然、时间递推、后验和拒识；默认参数是未训练专家初值。
只有已训练、已接受且未过期的 ENTRY 结果，才可强化同侧当前暗岛确认，不能单独生成道路。
接口接入不等于场地训练完成，更不等于已有实车导航收益。类 SLAM 与学习控制不在当前闭环中。

### 3.5 启动现状与采集现状

**C31 软件现状（2026-10-28）：** switch 保留 C26 ON + 连续五帧有效道路等资格及 OFF 停止语义。
独立 auto-track 不采样 C26/C27；新鲜、不同序号的有效近远观测须在采集/前台双时间上连续覆盖 3000ms，再检查 review、轮速及故障准入。同帧轮询不积累资格，计时中无效/过期会重置连续性。
默认 `MIDTERM_VISUAL_REVIEWED=0`，构建仍锁止；运行后无效观测、STOP/故障锁止，旧开关/UART 入口不能重新授权。跨普通 MCU reset 的真实断电锁止语义尚未证明。
上述已通过主机模拟，尚无板端及实车验收；第 4 节 R4 仍待完成。

文字遥测已有目标/反馈/PWM、路径、圆环、支持度、处理耗时与帧间隔。
94×60 图像工具目前用于停车摆位或手推，图像模式会撤销运行输出。
实拍缩略图与派生镜像可复现部分漏检，不能冒充全分辨率、自动驾驶同步时序或人工训练标签。
运动中图文复用仍待设计，见 F2。

工具兼容性软件更新：`field_protocol.ps1` 白名单已覆盖 C31，协议主机回归 50 checks 通过，拒绝 C32/额外后缀；被动接收不使用该白名单。没有打开串口，不能据此宣称板端握手已验收。
