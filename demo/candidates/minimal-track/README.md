# R13 最小赛道候选

版本 `MPC_R13_MINIMAL_20261111_1`。实现 [ADR-0002](../../../docs/adr/0002-r13-minimal-track-baseline.md) 的首版软件分期，目标赛道见[提案](../../../docs/changes/planner-authority-design-20261111/MINIMAL_TRACK_PROPOSAL.md)。这是待实车验证的候选，尚未证明完整赛道、环形绕行或启动保护的实车表现。

## 源码与职责

这里的 `code/` 是独立维护的应用源码，源于 `R13_V2_START_GUARD_20261111_1`，不读取根目录正在修改的 `demo/code/`。`baseline-code-sha256.json` 保存引入时的原始应用文件身份，当前实现差异见发布报告。`sdk-lock.json` 固定共享 SDK、用户入口、链接布局和 IDE 选项；其中基础 `uvoptx` 由当前仓库提供，其余来自冻结发布并核对原清单。

生成器不依赖历史 `.build` 或发布 ZIP；`baseline.json` 中的发布路径及哈希仅用于追溯。修改应用请改本目录，重新生成新输出目录，不在生成树里长期维护补丁。

| 职责 | 首版实际实现与接口 | 后续替换位置 |
| --- | --- | --- |
| 视觉与元素证据 | `vision_midterm_process` → 当前路径、有效性和环形状态；外层附帧号与采集时间 | 保持证据语义，替换内部检测 |
| 运动决策 | `vc_observe` / `vc_poll` → R13 转向与动力请求，R13 轮速目标规则 | 未来规划器在此提供经准入的运动目标 |
| 轮速执行 | `vision_speed` → 配对的 R13 私有 PI → 最终请求快照 | 独立调整执行层，不另设动力所有者 |
| 生命周期和输出 | C26、STOP、故障、帧/采样时效、版本复核 → 原最终 writer | 保留统一授权与输出边界 |

没有新增空转发框架。这里的 MPC 框架指职责及接口可替换，当前没有运行 MPC 求解器，也没有米制规划或影子链常驻。像素及归一化量仍保留原单位。R13 原参数、目标规则、PI 与启动保护候选成对保留；不继承 R4 的一秒截止或一次加载实验限制。

## 本次环形交接

在原当前图像识别上恢复外侧弧线资格检查，入口之后须看到连续弧线证据才允许识别出口；出口需要连续当前开口和路径证据，回到普通道路后才产生完成事件。短暂出口闪断不计完成。

已知赛道的顺序辅助采取最小实现：本次 C26 运行最多接受两次环形事件，完成后抑制第三次入环；OFF/新运行清零。`vision_midterm_route_progress` 可查询状态。没有引入定时转向、按轮程强制出环或新图像/路径录制。

**两次视觉事件不等于两处环形各绕了一整圈。** 目前无姿态/角度真值与实车连续轨迹来证明绕行角度，也不能仅凭次数判断中央/右上物理位置。入口、弧线、出口门槛仍需对应场景的实车验证；误识别的事件可能消耗两次预算。返回 A 的自动识别与停车不在首版承诺内。

## 再生与检查

在仓库根目录运行，输出目录必须是 `.build` 下尚不存在的新目录：

```powershell
python tools/prepare_minimal_track.py --output .build/mpc-r13-minimal-local --build
python tools/testing/run_tests.py --profile Host --suite minimal-track --compiler gcc --jobs 1
```

生成普通构建工程 `MPC_R13_Minimal.uvprojx` 和下载工程 `MPC_R13_Minimal_Download.uvprojx`，Target 均为 `nor_sdram_zf_dtcm`。生成器只编译和导出，不烧录、复位、连接串口或启动小车。下载工程只是供后续人工审查使用的入口。

输出包括 `candidate.json`、AXF、BIN、MAP、反汇编和日志，记录构型、源码/产物哈希与未实车验证状态。当前源工程中的构建前后命令全部禁用。SDK 身份不符即拒绝生成；不允许覆盖已有输出。

专项回归覆盖冻结 R13 的完整控制链构造输入差分、灰度入环/出环事件、C26/STOP 及启动反向保护。它们均为 Host 测试，不替代相机、舵机方向、板端实时性、动力响应与完整实车路线验收。
