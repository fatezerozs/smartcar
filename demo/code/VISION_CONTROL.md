## 泛用性与边界

参考赛道是亮色（白色）通道、较暗外侧（蓝色也可，只要灰度可分），需要处理直道和左右弯道，不写死 A/B 坐标、圈数、某张截图上的边界、转弯时长或赛道厘米宽度。
188×120 是当前相机接口尺寸，不是赛道模板；94×60 只是预览尺寸。图像区域、最小宽度和连续性门限在 `vision_profile.h` 中按图像比例配置。
`valid` 是规则通过，`q` 是有效行覆盖，不是正确率。缓慢漂移、连续背景假通道、反光、遮挡、过急弯仍可能误识别；这不是通用语义道路识别或已经完成的全赛道导航。
直道/弯道并不包含自主规划环岛、十字、分岔或目标点自动停车。最长运行时间只用于安全停机，不是按时间走赛道。

## 相机安装偏移与标定

配置项集中在 `vision_profile.h`，控制器本体也支持用 vc_config_t 提供经过验证的配置。

1. 在**确认笔直、车身位于实际赛道中间且朝向正确**的基准位置，机械固定镜头。不能用地面胶带接缝当中线；不要在弯道或未知朝向采集零点。
2. 在 near_y、far_y 附近读取真实双边中点，除以图像宽度减一，记录 axis_near_x、axis_far_x；y 同样以图像高度减一归一化。两点形成车身前向参考轴 x_ref(y)。
3. 近处与远处轴允许不同，近似补偿相机横向偏置/偏航。控制误差为 `(中点-x_ref)/该行半路宽`，对近/远有效行带分别平均；原串口 err 仍表示相对于图像中心的像素误差，不与校准后 DRIVE near 混淆。
4. 用保持车头不变的左右平移确认误差方向；用架空车轮的静态舵机试验确认正命令实际右转。机械改了相机高度、俯仰、横向位置、偏航或舵机连杆后，需要重新确认标定。
5. 两点轴不是完整相机内外参或地面单应性。明显滚转、强透视/畸变优先机械校正或做完整标定，不能指望两个数自动解决任意安装。

运行过程中不自动“把平均 err 归零”，不在弯道偷偷重置参考轴，也不从一张可疑叠线截图直接生成标定值。没有可信标定时保持锁定。

## 控制方法

每个通过复制校验的新帧运行一次，不靠发送图像的 1fps 节奏控制。

- 近行带必须有足够双边实测，不用纯历史补线授权驱动；远行带也只用双边实测。
- 横向误差 e 为近行带的归一化偏差。方向指标 h 为远、近归一化偏差之差，不是已标定的实际航向角。
- 转向目标为 `Kp*e + Kd*滤波变化率 + Kh*h`，按真实帧间隔计算，限幅到 [-1,1] 并限制转向变化速率。没有积分项，避免丢线后残留积分输出。
- 电机目标为配置的 cruise_duty，根据 |e|、|h|、转向量和行覆盖降低；远处不足再减半。只限制占空比上升，异常下降直接生效。
- 两电机使用同一有界前进占空比，沿用已存在的 PWM/DIR 宏，不进行带动力反转制动，不套用故障编码器的 PID。此版没有轮速差速闭环，也没有光流测速或里程积分。

**无轮速/电流反馈时不能保证实际车速、不能可靠判定堵转、打滑或某一电机停转；低占空比也不能直接宣称某个安全速度。** Kp/Kd、参考行带、输出上限及斜率是集中配置的待调参数，不是已经标定的万能值。

## 状态与异常

DISARMED → 连续新鲜有效帧 + 完整标定配置 + 串口 a（远程心跳）或 FIELD_4 已恢复配置的 C12 两秒本地启动（无需远程心跳）→ RUNNING。C12 是两种运行源的主开关，不是只对本地源有效。
RUNNING 出现异常 → FAULT，立即下发电机及舵机 PWM=0；图像恢复不能自行重启。
FAULT 只有人工 c 清除后回 DISARMED，重新积累有效帧、再人工 a 才能启动。s 停止，h 只续指令租约，不启动也不续相机租约。

| 异常 | 动作 |
| --- | --- |
| 低对比度、无路、覆盖不足、近处无双边实测、横向误差过大 | 撤销输出，锁存视觉/偏差故障 |
| 帧过期、同毫秒伪新帧、主循环长间隔 | 拒绝旧证据；运行中撤销输出并锁存 |
| 控制更新/相机帧超过默认100ms未提交 | 主循环检查 + 每10ms PIT1整数检查，撤销输出 |
| 超过默认500ms没有 h | 指令租约失效，锁存；迟到的 h 不复活故障 |
| 单次解锁达到默认5000ms | 安全超时；不是赛道运行时长估计 |
| 发送 g/b/o/p/r/f/m | 先撤销输出并解除运行；同批后续 a 不能覆盖停止 |
| 非法配置/非有限数值 | 禁止解锁或锁存故障，输出归零 |
| 外部故障 | 提供 vision_drive_trip 接口；需要真实接线和采样才能称为硬件故障检测 |

PIT1 只做时间及锁存检查，不做识别、不打印、不读故障编码器；输出临界区防止主循环在安全中断停机后重新写入非零 PWM。PIT0 的编码器/PID 写输出代码已移除，仅保留中断清标志。
PIT1 不是独立硬件看门狗：关中断卡死、芯片失控、功率器件故障等情况下不能保证撤销输出。还需硬件急停/电源切断、适当的硬件看门狗及接线验收。PWM=0 不等于瞬间机械停稳或已验证制动距离。
帧时间戳取自通过复制检查的新帧开始处理时刻，不是传感器曝光时刻；100ms 是接受帧/控制提交租约，不能宣称从真实曝光或物理停流开始精确100ms停车。当前也不能识别传感器重复输出完全相同内容这类故障。

## 驱动原理图限制

已查看用户提供的 DRV8701E 双电机驱动原理图 V1.1.1：P3 为两路 PH/DIR、EN/PWM 和 GND；U1/U3 的 nFAULT、SNSOUT/SO 标为未连接，nSLEEP 接使能开关，不是已确认的 MCU 急停输入。
因此当前没有假装读取 nFAULT、电流或电压，也没有擅自指定 GPIO/ADC。要做堵转、过流、低压和驱动温度的实测异常管理，需要先确认可用信号、接线、电平和阈值，再增加采样；不能仅靠相机判断。

## 启用前的硬件确认（本次没有启用）

- 本地 main.h 中电机注释与宏存在左右/引脚不一致：实际宏 M1 PWM=C6、DIR=C7；M2 PWM=C8、DIR=C9。该文件是预存改动，本轮没有替用户改映射。必须核对真实线序、每个电机前进极性和两轮方向后，才可确认 profile。
- 确认舵机中位、最小/最大安全脉宽、实际向右的符号，配置非零值；0 不是可以发送的脉宽，而是拒绝解锁的标记。不能只把一个 enable 改成 1 就跑车。
- 相机标定确认、硬件 profile 确认、非零且经验证的电机占空比上限/巡航值缺一不可，之后还需 a 人工解锁。当前全部安全锁保持原样。
- 现有串口命令是单字节调试接口，不是抗重放/认证的工业遥控协议。实际调车还需要可随时操作的物理急停和安全区域。
