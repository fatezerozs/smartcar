# 视觉静态调试与逐飞助手 V2

当前说明：2026-10-19。工程入口 `demo/mdk/base/rt1064.uvprojx`，目标 `nor_sdram_zf_dtcm`。不启动屏幕、故障编码器、原速度 PID/PIT0。现场版已编入控制器，上电未标定、PWM 配置为零且停车；新增串口调参见 [MIDTERM_FIELD](../../docs/archive/history/MIDTERM_FIELD.md)。

## 识别路径

处理 MT9V03X 的 188×120 灰度图：ROI 大津参考阈值、2%–98% 分位对比度检查、各行独立大津阈值、横向三像素去噪，再从近到远寻找白色通道。行对比度不足时退回 ROI 参考阈值，不把无边界行当作测量。检查中点和左右实测边界连续性；最低评分完全同分时拒绝该行，不按扫描顺序任意选左。

只有近期双边实测历史才允许短暂单边推算；推算必须容纳可见白色区域。拒绝的行不计覆盖、不写历史、不画叠线，整帧有效才提交宽度历史。连续性门限按图像比例配置，但仍是待实车确认的工程参数，不能保证消除连续背景假通道或适应所有急弯。

复制图像前短原子区确认完成标志与缓冲指针，复制后检查切换，拒绝检测到的竞争帧；不宣称检测所有传感器故障。处理帧间隔超过 250ms 清除历史，连续 2 秒无接受帧输出 NO_FRAME。

当前算法针对亮色通道、较暗外侧；不是跟单条黑线走。几何和参考轴集中于 `vision_profile.h`，不从某张截图写死赛道模板。相机安装偏移须按控制说明标定，不在未知弯道自动归零。

## 串口与命令

1. 完整工程编译成功后，使用你们已确认的供电、接线和下载流程；没有确认之前保持电机物理安全隔离。
2. 打开实际枚举的串口，不要写死 COM10。设置 115200、8 数据位、1 停止位、无校验、无流控。
3. 串口助手关闭自动发送、HEX 发送和自动追加换行；复位一次并等待启动。默认约 500ms 一组 `[VISION2]`。`n` 增长说明有新帧接受并处理。
4. 发送普通单字符即可，大小写均可。若使用 HEX 发送，则发送下表对应的一个字节，不要把字母字符串当 HEX。

| 普通字符 | HEX 字节 | 功能 |
| --- | --- | --- |
| `?` | `3F` | 切回文字，显示帮助 |
| `t` | `74` | 文字诊断 |
| `g` | `67` | 原始灰度缩略图 |
| `b` | `62` | 二值缩略图（灰度格式的 0/255 像素） |
| `o` | `6F` | 灰度叠线：实测边界为灰色，中线黑色；推算中线灰色；无效帧只显示灰度 |
| `p` | `70` | 暂停输出，后台继续处理 |
| `r` | `72` | 清除识别历史，保持当前输出模式 |
| `f` / `m` | `66` / `6D` | 完整赛道观测 / 中期控制；切换先停车、清历史，保持当前显示模式 |
| `a` / `h` / `s` / `c` | `61` / `68` / `73` / `63` | 控制扩展：人工解锁 / 心跳 / 停止 / 清故障；默认禁用输出，详见控制说明 |

先在串口助手发 `g` 或 `o`，再打开“图像传输 → 实时图像”。宽高由数据包携带，不需要手填。回串口助手发 `t` 恢复文字。发图时看不到文字本身不是故障。

## V2 数据与帧率

固定 94×60 预览头：`AA 49 02 02 5E 00 3C 00 01 00 00 00`，其后 5640 字节像素，总计 **5652 字节/帧**。这是逐飞 V2 灰度格式；二值模式不是位打包。包头使用显式字节，不依赖结构体填充。

115200、8N1 下仅一帧发送就约需 0.49 秒，发送端约每 1.5 秒发一张；这不是处理算法的实时帧率。图像发送是阻塞调试操作；未来启用控制后，`g/b/o/p/r` 会先撤销运行输出。不要用图传模式跑车。

此前用户实机截图确认过 94×60 灰度/叠线和静态 TRACK，文字处理帧率约 48–50。此后连续性和控制扩展仍以离线验证为主，不能把旧截图当作本次新代码完整实车验收。

## 诊断字段

| 字段 | 解释 |
| --- | --- |
| `valid` / `state` | 当前规则是否通过；TRACK、NO_LANE、LOW_CONTRAST；断流另有 NO_FRAME |
| `q` | 有效行覆盖评分 0–100，不是正确率或概率 |
| `thr` / `contrast` / `white` | ROI 参考阈值、2%–98% 灰度分位差、白像素百分比 |
| `row90_thr` / `local_rows` | 原图第 90 行阈值 / 行阈值与 ROI 参考值不同的行数 |
| `both` / `inferred` | 双边实测 / 单边推算行数 |
| `err` / `raw` | 相对图像中心的加权像素偏差，滤波 / 未滤波；正为画面右侧。不是标定后的控制归一化误差 |
| `bend` / `bend_ok` | 远减近的中线差及其有效性，仅用足够双边实测 |
| `row90 L/M/R` | 原图第 90 行左右边界/中线；-1 表示无效，不拿画面边缘当真实边界 |
| `ambiguous` | 最低评分完全同分而被拒绝的行数，不覆盖所有歧义情形 |
| `fps` / `proc_ms` | 实际处理帧率 / 最近算法毫秒耗时，非摄像头标称帧率 |
| `age_ms` | 距最近接受帧开始处理的时间，不是距真实曝光时刻的延迟 |
| `drop` | 空缓冲或检测到复制竞争而放弃的计数，不是全部丢帧 |
| `history_reset` | 自动长间隔历史清理计数，不包含手动 r 和断流清理 |

## 空白与误识别排查

- 暂停/图像模式不会持续输出文字。保持当前连接，发一次 `?`，等待数秒；关闭其他占用串口的软件，确认端口和固件版本。不要只勾“显示发送”就认为已经收到板端响应。
- 如果文字和图像均无响应，先记录接收字节数和供电状态，再断开串口、确认端口、重连，按一次核心板复位并等待。多次快速按复位会反复中断启动，不是增强复位。
- 曾出现间歇无输出并在纯 UART 诊断后恢复，根因没有证实。本交付不保留 `[UART_DIAG]` 固件，不声称视觉算法改动修复了串口链路。
- 叠线必须位于真实赛道两边之间。`valid=1` 仍可能是背景误识别；不要只看 q 高。保留对应灰度/二值图与日志，确认安装和曝光后再调几何参数。
- 无实车时只运行合成回归、检查图像链路和偏差方向；它们不能证明停车距离、速度或全路线稳定性。
