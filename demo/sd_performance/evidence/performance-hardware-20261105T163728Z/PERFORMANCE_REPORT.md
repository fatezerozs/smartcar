# SD 实板写入性能测试报告

日期：2026-11-06（Asia/Shanghai）。原始串口时间戳使用 UTC，测试对应本地约 00:37—00:38。
结论：**1-bit、3.3V 策略、CPU 600MHz 下，24.75MHz 与 49.5MHz 两档的 16MiB 文件写入及全量回读校验均通过。** 本轮最佳纯写入 I/O 为 2095KiB/s，包含处理和最终同步的平均写入为 1809KiB/s。不是 SD 卡绝对极限或长时间稳定下限。

## 执行过程与安全边界

用户已烧录性能版。代理打开 COM14（115200、8N1、无流控，DTR/RTS 禁用），读取 `SDPERF v1` 标识及 CPU 600MHz 状态，再执行 BASIC。BASIC 成功新建 `2:/S0000002.BIN`，写入/回读 64KiB，pass=1、errors=0。随后执行 BENCH25，成功后才执行 BENCH50；最终 PERF RESULT 再次确认结果，端口已关闭。
未打开 COM10；未由代理烧录、下载或复位；未删除或覆盖既有 SD 文件、格式化或修改分区；没有启动车辆业务。
每档先预分配连续 16MiB，新文件使用 CREATE_NEW；固定 256 次 64KiB 写入，f_sync/关闭后重新打开并逐块完整校验。此次新增文件总量 32MiB+64KiB，全部保留。

## 如何理解“极限”

49.5MHz 单线原始数据比特率算术上界为 6.1875MB/s（约 5.901MiB/s），协议开销会降低文件吞吐。本轮纯读取已达约 5.064MiB/s，写入明显更低且出现约一秒长延迟。长延迟提示实时记录需要缓冲，单次样本不能保证延迟上限；未用总线分析仪确定延迟来自卡内部、FAT 或驱动的具体比例。
`write_io_KiBps` 是 f_write 耗时之和计算的平均值，不含 CRC 生成、预分配与最后同步；`write_sync_KiBps` 包含写入处理及最后同步，仍不含预分配成本。实际记录能力应优先参考后者，并考虑峰值延迟和未来业务占用。
600MHz CPU、指令缓存和大块传输与上一轮 CPU24MHz 的 185KiB/s 配置不同，不能将所有增速归于 SD 时钟翻倍。
3.3V 为固件配置报告，未仪表实测。50MHz 档已通过实际 clock_hz=49500000、timing=1 与数据校验确认，不是仅打印请求值。
没有测试 4-bit、1.8V、UHS、超频、长时间稳态、断电持久性或生产控制并行负载。本报告没有将 16MiB 短测认定为物理绝对极限。

## 证据与工作区保护

原项目及既有 SD Diagnostic 的 1219 项基线中，变化项为 []。性能版构建输入中与交付哈希不同的文件为 ["demo\\sd_performance\\mdk\\sd_performance.uvprojx"]；没有根据哈希推断具体原因，没有覆盖这些文件。其余输入与交付匹配。
没有通过调试器读回 Flash，无法独立证明实板镜像与交付 AXF 逐字节一致；结论针对实际响应 SDPERF 命令并完成上述校验的当前固件。
